# 자체 학습 AI·Gomocup 엔진 개발 계획

갱신일: 2026-10-28. 최종 목표는 **지도학습과 강화학습을 기반으로 강력한 자체 오목 AI를 개발하고, Gomocup에서 실행·대국할 독립 엔진으로 완성하는 것**이다. 주 산출물은 자체 모델·추론/탐색 엔진·소스/실행 파일·재현 가능한 검증 자료다. 기존 GUI는 관찰/오류 분석 도구이며 전체 GUI 완성은 학습 착수 조건이 아니다.

이번 작업은 문서/개발 방향 정리만 수행한다. 아래 기능은 계획이며 자동 착수하지 않는다. 과거 승인·우선순위는 [승인 기록](requirements-pending.md)과 [이전 계획](history/development-plan-through-2026-10-24.md)에 보존한다. 현재 지침은 [AGENTS](../AGENTS.md)·[학습/데이터/평가 원칙](learning-and-evaluation.md)을 따른다.

## 실제 기반과 근거

2026-10-28 코드 확인 기준 `fda491fcd17ac83a6203c2d9741cde63a65985da`다. 이번에는 빌드/실행을 반복하지 않았고 아래 검증은 과거 기록이다.

| 영역 | 실제 구현 | 검증/남은 범위 |
|---|---|---|
| state/rules | 독립 C++20 상태·구조 검사·렌주 판정, evaluate에200수 정책 | [상태](verification-state.md)·[규칙](verification-rules.md) 회귀/고정 심판 함수 대조. 모든 배치/최종 대회 심판 적합성 아님 |
| opening/match | PreparedRenju/DirectRenju, 별도 Swap2 구조 전환, 권한/사본 적용/결과/Token | [처음부터 검증](verification-direct-start.md)·[계약](match-contract.md). Swap2는 RuleContractRequired, 공식 준비 데이터 미확보 |

C++20·Win32·CMake와 기존 빌드 스크립트/ASCII 경로 우회는 유지한다. 루트 CMake는 Windows x64 전용이며 코어의 Windows 독립성이 전체 학습 빌드의 이식성을 증명하지 않는다. Python 학습·프레임워크·추론 런타임은 별도 검토하고 기본 GUI/C++ 빌드에 강제하지 않는다.

## 우선순위와 단계별 완료 기준

규칙 정확성 → 자동 대국·데이터 기반 → 지도학습 → 탐색 결합 → 자기 대국 강화학습 → 성능 평가·제출 검증 순이다. 프로토콜 최소 동작 검증은 초기에 병행하고 이후 각 단계에서 회귀한다. 단계 완료는 구현/시험 증거를 남긴 경우에만 기록한다.

| 단계/목적 | 범위·산출물 | 선행 조건 | 검증·완료 기준 |
|---|---|---|---|
| A. 공통 환경/규칙 정확성 | 기존 코어를 재사용하는 무화면 상태/합법 수/착수/결과/초기화/복원 경계, 현재 규칙/종료 프로필 식별 | 현행 계약/회귀 근거 확보 | 초기화/복원·거부 시 보존·종료/오프닝 차단·합법 마스크/실제 착수 일치·좌표/참가자/관점·기존 회귀. GUI 없이 재현 가능 |
| B. 자동 대국/데이터 기반 | 반복 대국·흑백 교대·배치 지정·실패/처리량 기록, 기보 저장/변환, 출처/권리/규칙 메타데이터, 중단/재개, 대국 단위 분할 | A의 인터페이스, 데이터 사용 권리/오류 라벨 정책 | 순서/오프닝/종료 사유 복원, 중복/변형 중복·분할 누출 검사, 동일 시드/설정 재현, 중단 후 중복 방지 재개. 정상 결과와 오류 통계 분리 |
| B와 병행: 초기 수신 프로토콜 | GUI/외부 제어와 별도인 자체 엔진 최소 수신/합법 응답 시험기·통신 회귀 | A의 합법 응답/좌표 경계, 기존 공식 자료 재확인 | 실제 관리기/고정 하네스에서 선언한 명령·BOARD 복원/색/순서·END/오류 확인. 모의/기본 응답기를 강한 모델로 소개하지 않음 |
| C. 지도학습 초기 모델 | 검증된 데이터·정책/가치 표현 후보 비교·학습 코드/체크포인트·재현 설정 | B의 데이터/분할/권리와 규칙 계약, 장비/프레임워크 선정 근거 | 작은 데이터 학습/복원·검증 지표·누출 검사·별도 대국 평가. 손실 감소와 실력 개선을 구분 |
| D. 추론/탐색 결합 | 모델 내보내기/로딩·C++ 추론·탐색 인터페이스·비교 보고 | C 모델/입출력 계약, 추론 런타임/배포 권리 검토 | 학습/엔진 추론 동등성·지연/메모리, 같은 예산의 모델 단독/탐색 비교, 프로토콜 회귀. MCTS 등은 검토 후 선택 |
| E. 자기 대국 강화학습 | 경험·보상·정책 목표·업데이트·체크포인트 승격/되돌림·중단/재개 | D, 보상/기권/오류 대국 정책 확정, 재현 기반 | 경험→업데이트→보류 평가/승격의 재현, 이전 모델/다른 상대·배치와 비교. 외부 엔진 대국만으로 완료 선언 금지 |
| F. 실력/제출 검증 | 여러 상대/보류 배치·흑백 교대·탐색/시간 조건 평가, 독립 엔진 ZIP·고지·검증/제출 안내 | 대상 연도/리그/공고·서버 환경·권리/의존성 확정 | 표본/불확실성·오류/처리량 보고, 수신 프로토콜·대상 심판/시간/CPU/메모리/오프닝·배포 환경 검증. 실제 등록/서명/업로드는 별도 요청 |

GUI 편의 기능·GUI 복기·클린 Windows GUI 배포는 보조 작업으로 추적한다. 기존 사람용 승인 기능을 삭제하지 않되 A~E 진입 관문으로 삼지 않는다. 목표 서버에서 **제출 엔진 자체**의 실행/의존성 검증은 F의 필수 사항이다. 기존 외부 매니저 활용 요구는 반복 평가/제출 검증에서 계속 추적한다.

## 프로필·미정 선택

- 15×15 렌주를 잠정 개발 기준으로 유지한다. 현재 PreparedRenju/DirectRenju/Swap2 경계를 유지하고 규칙을 임의 변경하지 않는다.
- 기존 시간30초/180초·메모리1GB·한 코어·pondering 금지·200수·전문가 오프닝은 2026-10-19~23 조사한 일반 렌주 잠정 프로필이다. 학습 설정과 구분하며 전 대회/학습 공통 상수로 확정하지 않는다. 현 구현의 고정200수/GUI 제한은 향후 설정 분리 전까지 그대로다.
- 정책·가치 모델/MCTS는 우선 검토 후보다. 모델 구조·탐색·학습 장비·Python/프레임워크·내보내기/추론 런타임·기보 형식은 이번에 확정하지 않는다.
- SWAP2BOARD의 기존 별도 요구와 목표 리그의 필수 여부를 구분한다. 목표 연도/리그·공식 데이터 사용 조건·오류 대국 보상 정책·강함/승격 평가 기준은 [미정 목록](requirements-pending.md)에 남긴다.
