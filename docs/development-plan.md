# 전체 개발 계획과 완료 기준

2026-10-19 최초 구현 착수 승인은 기반 구성·기본 GUI 창·빌드·실행까지였다. 이후 범위는 아래 후속 승인과 최신 사용자 지시를 따른다.

후속 갱신: 같은 날 상태 모델·관련 자동 테스트를 승인받아 구현했다. 2026-10-23에는 렌주 명세·판정·자동 테스트·고정 심판 대조도 승인받아 구현했다. 당시에는 기반 창·상태·순수 규칙까지 구현했다. 현재 상태는 아래 후속 갱신을 따른다. [상태 검증](verification-state.md)·[규칙 검증](verification-rules.md)을 따른다.

후속 오프닝 승인: 준비 배치 로더·순차 복원·본게임 인계·독립 Swap2 상태 전환과 자동 테스트를 구현했다. 오프닝 단계에서 67개 CTest를 사용했으며 [오프닝 계약](opening-contract.md)·[최신 검증](verification-opening.md)을 우선한다. 후속 로컬 대국 구현은 아래 최신 상태를 따른다.

2026-10-24 로컬 대국 검증 재개: WIP `5023aa2`를 보존하고 match·GUI·금수 작업자 코드를 검토했다. 빌드/install·81개 테스트·DLL 검사는 통과했다. GUI 도구 입력 충돌로 실제 착수 검증은 남아 있으며 [match 계약](match-contract.md)·[최신 검증](verification-match.md)을 따른다. 당시 승인에서는 AI로 확대하지 않았으며 아래 후속 승인을 따른다.

## 현재 확인한 자료
루트 AGENTS.md와 docs/requirements-pending.md, docs/compatibility-research.md가 실제 존재하며 읽었다. 이번 확인에서 참조 문서 누락은 없었다. 기존 문서의 승인 이력은 보존하고 이번 구현 착수 승인을 추가한다. 기존 조사만으로 실제 연동 완료를 주장하지 않는다.

## 단계
| 단계·목적 | 범위·산출물 | 검증 | 완료 기준·현재 상태 |
|---|---|---|---|
| 1. 대회·호환성 근거 | 승인 기록, 매니저·엔진 후보·라이선스·연동 방식 비교 | 공식 문서·고정 버전 소스 확인, 이후 실제 프로토콜 시험 | 제품 정책 확정. 후보 조사 완료, 목표 리그·실제 연동은 후속 과제로 열어 둠 |
| 2. 프로젝트 기반 | C++20·Win32·CMake, 분리 타깃, 기본 창, 빌드·배포 스크립트·README | x64 빌드, 창 표시·재그리기·종료, DLL 의존 검사·설치 스테이징 | 이번 작업 대상. 실행 결과는 verification-foundation.md에 기록 |
| 3. 상태·렌주 | 상태 저장·구조 검증·순수 렌주·200수 정책 | 현재 상태·규칙 CTest 53개, 고정 심판 2,264개 보드·6개 경계 대조 | 명세의 구현·회귀·함수 대조 완료. 모든 배치/최종 운영 심판 호환성·성능은 미확정 |
| 4. 오프닝 | 준비 배치 로더·복원·종료/200수·인계, 별도 Swap2 전환 | 오프닝 14 CTest, 원본 초기화·좌표 함수·Swap2 네 경로 실행 비교 | 구현·회귀·유효 입력 대조 완료. 공식 렌주 데이터/재배포 권한 미확보, Swap2 규칙 바인딩 미해결. 문자열 통신은 6단계 |
| 5. GUI·사람 대 사람 | match·15×15 표시/입력·비동기 금수·기권·재시작 | 14개 match CTest, 실제 시작→착수→종료→재시작 | 구현·81개 전체 회귀 통과. 실제 GUI 대국 검증이 남아 단계 미완료. 시계는 이번 범위 밖 |
| 6. 외부 AI | 실행 파일 선택, stdin/stdout·Gomocup·Swap2, 비동기·시간·자원·프로세스 정리 | 먼저 모의 AI 오류 주입, 이후 실제 엔진·매니저와 로그 비교 | 사람 대 AI·AI 대 AI 완료, 오류 정책·충돌 중단·무재시도·재시작 정리 통과 |
| 7. 기보·관전 | 저장·불러오기·종료 후 복기·AI 대 AI 일시정지 | 돌·차례·시간·선택 이력 복원, 다음 AI 요청 경계에서 정지·재개 | 승인 기능 전체 통과, 무르기·온라인·제한 완화 미포함 |
| 8. 통합·배포 | 소스·실행 ZIP·사용 안내·라이선스·검증 보고 | 개발 도구 없는 Windows 10·11 x64에서 세 모드 검증 | 대상 환경·의존성·자원 정리 확인, 미검증·알려진 제약 공개 |
| 9. 자체 AI 별도 단계 | 이후 별도 지시에 따라 자체 엔진·목표 리그·제출물 준비 | 정확한 참가 연도의 공식 심판·프로토콜·자원 조건과 실대국 | 게임·외부 AI 검증 완료 후 시작. 지금은 알고리즘 개발하지 않음. 실제 제출은 별도 명시 지시 필요 |

1단계의 실제 연동 검증은 통신 구현이 필요한 6단계까지 이어진다. 아직 엔진을 연결하지 않고 2단계로 진행하는 것은 이번 요청의 명시 범위를 따른 것이다. 실제 연동이 가능하다고 미리 확정하지 않는다.

## 모듈 구성과 의존 방향
| 디렉터리·타깃 | 책임 | 현재 구현 상태 |
|---|---|---|
| src/app · omok | 실행 진입점·manifest·조립 | 구현됨 |
| src/gui · omok_gui/omok_geometry | Win32 보드·표시·입력·독립 좌표 변환 | 구현됨. 실제 대국 수동 검증 미완료 |
| src/state · omok_state | 바둑판·참가자·색·차례·이력·외부 결과 기록 | C++20 정적 라이브러리 구현. 판정·착수 권한은 담당하지 않음 |
| src/rules · omok_rules | 순수 구조 검사·국소 렌주·일반 대국 200수 정책 | C++20 정적 라이브러리 구현, 상태에 적용하지 않음 |
| src/opening · omok_opening | 준비 배치 로더·규칙 활용 순차 복원·인계·별도 Swap2 전환 | state/rules를 사용하는 정적 라이브러리 구현, GUI·프로토콜 독립 |
| src/match · omok_match | 대국·종료·Token·금수 작업자 | 독립 정적 라이브러리 구현. 시계 미구현 |
| src/ai · omok_ai | 외부 프로세스·BOARD 변환·CPU·오류/취소 | Win32 정적 라이브러리, 실제 Rapfi 초기 연결·사람 대 AI 확인. AI 대 AI/Swap2는 후속 |
| src/records · omok_records | 저장·복원·복기 | state 의존 경계만 예약 |

예약 타깃을 기능 구현으로 계산하지 않는다. 이후 구현 시 state에 Windows·GUI 의존성을 두지 않는다. match는 참가자 입력 인터페이스를 통해 사람·AI 요청을 처리하고, GUI와 AI 어댑터는 규칙을 중복 구현하지 않는다. 기보는 보드만 저장하지 않고 대국 설정·참가자 색 대응·오프닝 선택 이력을 보존하도록 설계한다. 실제 형식·인터페이스는 해당 단계에서 구체화한다.

현재 state API·좌표는 [상태 계약](state-model.md), 규칙과 향후 일반 대국 적용은 [판정 계약](rules-spec.md), 오프닝 입력 주체·색·차례·결과 복원은 [오프닝 계약](opening-contract.md)에 구체화했다. 일반 대국 권한·배치/종료 적용은 match가 담당한다. 시계는 후속이다. tests/는 GUI 독립 상태·규칙·오프닝·match와 좌표 테스트를 포함한다.

각 단계 보고는 변경 파일·실제 검증·미검증·남은 제약을 포함한다. 필수 요구 변경만 사용자에게 확인하며 승인된 기술 선택을 반복 승인받지 않는다.

## 첫 수부터 대국 (2026-10-24 추가)

사용자 후속 요청으로 빈 보드 흑 첫 수부터의 로컬/사람 대 Rapfi를 추가했다. GUI 초기 선택은 처음부터이며 대회용 PreparedRenju와 별도 DirectRenju 시작 계약을 쓴다. BEGIN과 첫 수 이후 수순 BOARD를 연결하고 CTest는89개로 늘었다. 실제 GUI 초반 교대와 Rapfi 양쪽 선후공을 확인했다. [새 계약/검증](verification-direct-start.md)을 따른다. 전체 AI/대회 단계와 기존 미검증은 완료로 표시하지 않는다.

## 외부 Rapfi 초기 연결 (2026-10-24 이전 기록)

사용자 설치 Rapfi와 CPU/설정/모델을 조사하고 준비 렌주에서 실제 응답을 match에 적용했다. GUI 사람 대 Rapfi의 흑/백 응답·사람 클릭·재시작·기권·취소/닫기를 확인했다. 전체 CTest는86개이며 실제 엔진 probe와 구분한다. 6단계는 초기 연결만 구현한 상태로 AI 대 AI·Swap2 통신·전체 대회 시계/자원/오류 실대국·매니저 검증은 남아 있다. 5단계의 승리/금수/무승부 등 남은 전체 수동 항목도 자동 완료 처리하지 않는다. [계약](rapfi-integration.md)·[최신 검증](verification-rapfi.md)을 따른다.
