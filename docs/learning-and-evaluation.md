# 자체 학습·평가 기반 설계 원칙

2026-10-28 사용자 목표 확정에 따른 **계획/요구사항**이다. 아래 학습 환경·데이터 파이프라인·자체 제출 엔진은 아직 구현하지 않았다. 현재 C++ 계약과 실제 검증은 [개발 계획](development-plan.md)·[인계](handoff.md)에서 구분한다.

## 산출물과 의존 경계

| 영역 | 책임 | 경계 |
|---|---|---|
| 공통 C++20 코어 | 상태·렌주 판정·시작 배치·대국 권한/종료 | GUI/학습 프레임워크/추론 런타임에 의존하지 않음 |
| 학습 환경 | 데이터 처리·지도학습·경험 생성·자기 대국·업데이트·평가 실행 | Python 등 별도 언어 가능, 기존 GUI/기본 빌드에 학습 의존성을 강제하지 않음 |
| 제출 엔진 | 모델 로딩·추론·탐색·Gomocup 명령 수신/응답 | 학습 프로세스·GUI 없이 배포/실행. 선택한 대상 OS/CPU/런타임 검증 필요 |
| 외부 엔진 어댑터/매니저 | Rapfi 등 별도 프로세스에 명령을 보내고 응답/오류 검증 | 기존 src/ai. 자체 엔진이 명령을 받는 구현과 별개 |
| GUI | 대국 관찰·수동 대국·오류 분석·보조 복기 | 전체 편의 기능·클린 GUI 배포 검증은 학습 착수의 관문이 아님 |
| 기보/실험 기록 | 대국·시작 배치·오프닝 선택·종료 사유·데이터/실험 계보 | 학습 데이터 저장/변환이 우선, GUI 복기는 별도 보조 기능 |

현재 루트 CMake는 Windows x64를 요구하고 기존 외부 엔진 어댑터도 Win32다. 코어가 Windows 헤더와 독립적이라는 사실을 Linux 학습/제출 환경의 빌드 성공으로 확대하지 않는다. 대상 확장·빌드 타깃 분리·Python 연동 방식은 해당 작업에서 검토한다. C++20 기반/현재 검증 빌드 경로를 보존한다.

기본 경로는 정책·가치 신경망의 지도학습 → MCTS 탐색 결합 → 자기 대국 강화학습이다. 구조·크기·입력 표현·행동 인코딩·MCTS 세부 설정/예산·장비는 검증을 거쳐 정한다. AI 모델·탐색·학습은 현재 단계에 필요한 최소 구조로 시작하고 실험/성능 측정에 따라 발전시킨다. 학습 Python/프레임워크·내보내기 형식·추론 도구의 성능, C++ 연동, Windows/목표 서버 배포, CPU 명령어, 모델/코드 라이선스를 비교한 기술 결정을 남긴다. 설치/학습/의존성 추가는 이번 문서 작업의 범위가 아니다.

AI 자체 외의 상태·규칙·오프닝·대국 제어·외부 통신·기보/데이터 입출력·평가 실행기·GUI·설정·로그·배포는 확장/교체를 고려한다. 모듈별 책임/인터페이스를 명시하고 GUI/OS/특정 엔진 의존성을 경계에 모은다. 새 저장 형식/실행 방식/엔진 때문에 핵심 로직을 광범위하게 수정하지 않도록 하며, 저장 데이터/공개 인터페이스의 버전·호환성·관련 회귀로 기존 동작을 보호한다. 구체적인 단계별 기준은 [개발 계획](development-plan.md)을 따른다. 미승인 기능 선행 구현·과도한 플러그인/추상화·원칙만을 이유로 한 대규모 재작성은 하지 않는다.

## GUI 없는 환경 인터페이스

계획 API는 상태 스냅샷, 현재 참가자/색/차례, 합법 수/마스크, 착수, 종료 여부/결과/이유, 초기화, 시작 Session 복원을 제공한다. 상세 wire 형식/함수명은 후속 구현에서 정하며 이 문서에는 실행 가능한 새 명령을 만들지 않는다.

- 기존 match를 유일한 일반 대국 쓰기 경로로 사용한다. start_direct 또는 원본 PreparedRenju Session을 보존해 시작하고, Token/actor 확인 → rules 판정 → 사본 적용을 거친다. 구조 오류/금수·정상/승리/무승부를 구분한다.
- 학습/평가와 실제 대국은 같은 규칙 계약을 사용한다. 다른 언어로 판정을 다시 만들면 삼삼의 재귀 예외·사사/장목·동시5목 우선·가장자리·수순 경계 등을 고정 사례와 무작위/변형 사례로 교차 검증한다.
- 합법 수는 프로필·단계·현재 색을 포함한 의미를 명시한다. 정상/승리/무승부로 둘 수 있는 빈칸과 흑 금수·구조 오류를 구분하고, 마스크 계산이 원본 상태를 바꾸지 않아야 한다. 실제 착수는 마스크/캐시와 별개로 match가 다시 검증한다. 종료 상태에는 다음 수를 요청하지 않는다.
- 오프닝 입력 권한과 본게임 차례를 구분한다. RuleContractRequired 상태를 합법 일반 착수로 통과시키지 않는다. 모의 보드 분석용 analyze_board와 일반 대국 evaluate의 책임을 혼합하지 않는다.
- 참가자A/B, 흑/백, 현재 관점의 own/opponent, 준비 돌의 placed_by 없음, 오프닝 제안/선택을 보존한다. 내부 row/column과 외부 x/y를 명시적으로 변환한다.
- 대국 ID·세션/보드 버전·스냅샷을 사용해 초기화/재개 뒤 이전 입력·비동기 응답을 차단한다. 실패 요청의 전체 상태 보존을 검증한다.

## 프로필과 반복 실행

대회 프로필은 조사일·대상 연도/리그·공식 근거·규칙/오프닝·수순/시간/메모리/CPU/pondering 조건을 함께 식별한다. 기존 잠정 프로필은 2026-10-19~23에 조사한 렌주 일반 기준이며 [호환성 조사](compatibility-research.md)를 따른다. 목표 참가 연도·리그는 미정이다.

학습 프로필은 경험 생성 속도·탐색 예산·병렬 환경·시드·시작 배치 분포 등 학습 조건을 별도로 기록한다. 규칙·오프닝·시간·자원은 명시적 프로필 ID/버전과 지원 범위로 관리하고 모듈마다 잠정 값을 새로 중복 하드코딩하지 않는다. 같은 렌주 판정이라도 대회 프로필과 같다고 주장하지 않는다. 200수·시간/자원·오프닝을 모든 학습/모든 대회의 상수로 고정하지 않는다. 현재 코드는 evaluate의200수와 GUI/외부 엔진 제한을 고정 사용하므로 향후 설정 분리에는 근거/영향과 관련 회귀가 필요하다. 이번 문서로 기존 실행 동작을 바꾸지 않는다. 사람용 무제한 연습 설정을 일괄 승인한 것으로 해석하지 않는다.

반복 대국·동일 배치의 흑백 교대·시드/시작 배치 지정 → 실행 취소/중단 기록 → 스케줄/완료 ID·설정·상태/시드·상대/체크포인트 검증을 포함한 재개 → 처리량 측정 순으로 확장한다. 중단된 대국을 완료 대국으로 세지 않으며 재실행/재개 전략과 중복 ID 방지를 정한다. 환경 초기화·수 판정/마스크·모델 추론·탐색·기보 기록·전체 대국의 시간/처리량을 구분해 측정한다.

정상 보드 승패/무승부, 기권, 금수패, 시간 초과, 엔진 시작 실패/비정상 종료/잘못된 출력/불법 수, 취소/중단/판정 충돌을 별도 필드로 보존한다. 기존 match가 오류를 상대 승리로 기록해도 그 종료 사유를 잃지 않는다. **오류 대국을 보상/가치 정답으로 사용할지, 제외/격리할지와 가중치는 별도 미정 정책**이며 결정 전 자동으로 정상 승패 보상과 섞지 않는다.

## 기보·데이터 수명

- 원본 불변 보관과 변환본을 구분한다. 출처 URL/제공자·파일/데이터셋 버전·해시·취득 시점·이용 조건과 권리 근거·규칙/프로필·오프닝·결과/종료 사유를 보존한다. 학습·파생물·모델 공개·원본 재배포의 허용 범위는 각각 확인한다. 다운로드 가능성이나 외부 엔진 실행 가능성은 허가가 아니다.
- 수순·좌표·돌 색·실제 참가자·색 배정/교환·오프닝 제안/선택/완료 이벤트를 분리한다. 제안된 준비 돌·Swap2 선택을 일반 본게임 정책 정답으로 무조건 쓰지 않는다. 포함/제외 기준과 인코딩 버전을 명시한다.
- 기권·시간패 등의 결과는 마지막 보드와 별개다. 5목이 없다는 이유만으로 손상 기보로 판정하지 않는다. 좌표/순서/중복/중간 종료 이후 착수, 결과 근거의 일관성은 해당 프로필로 검사하고 원인별 격리/수정 이력을 남긴다.
- 대국 ID/원본 계보를 기준으로 중복과 회전/반사·전치된 동일 대국 등 정의한 변형 중복을 점검한다. 연결된 중복 그룹은 같은 분할에 둔다. 그룹의 대표/정규화 방법과 해시 버전을 기록한다.
- **대국 단위로 학습/검증/최종 평가를 분리한 뒤 회전·반사 증강**한다. 같은 대국의 수나 변형이 다른 분할로 새지 않도록 검사한다. 시작 배치/상대 계보의 겹침도 평가 목적에 맞춰 기록/통제한다.
- 데이터 형식/스키마·전처리·필터/라벨 정책·증강·분할 시드·대국 목록/그룹 목록을 버전 관리한다. 학습 통계/제외 사유/권리 미확인 목록을 남긴다. 형식/저장 수단은 아직 미정이며 기보 저장을 GUI 복기 완성에 종속시키지 않는다.
- Rapfi 대국 기보/응답은 벤치마크 평가 기록으로 관리하며 현재 계획에서 지도학습 정답·강화학습 경험/보상으로 전용하지 않는다. 학습 데이터의 실제 출처/버전/이용 조건과 라벨 의미를 별도 확인하고 자체 모델과 외부 모델/코드의 출처를 혼동하지 않는다.

## 정책·가치 신경망 지도학습 → MCTS → 자기 대국 강화학습

1. 권리가 확인되고 규칙/수순/결과가 검증된 데이터로 초기 정책·가치 신경망을 지도학습한다. 데이터 분할·입력/정답 관점·합법 마스크·라벨 정책을 먼저 고정하고 작은 데이터 과적합/재현/체크포인트 복원을 검증한다.
2. 모델 내보내기/로딩·추론 동등성·지연/메모리를 확인하고 최소 MCTS와 결합한다. 모델 단독과 같은 자원 예산의 MCTS 결합을 비교한다. 모델 크기/구조·MCTS 설정·추론 도구는 측정 결과로 발전시킨다.
3. 자기 대국 경험(상태/행동·정책 목표·결과·보상·모델/탐색 버전) 생성 → 저장/검사 → 보상/목표 계산 → 모델 업데이트 → 별도 평가 → 체크포인트 승격/되돌림 절차를 구축한다. 보상·오류 대국·기권·샘플 재사용 정책은 구현 전에 근거와 함께 정한다.
4. 외부 엔진과 대국만 하고 업데이트하지 않는 것은 평가다. Rapfi는 중간·최종 성능 평가용 고정 외부 벤치마크로만 사용하고 학습 상대/정답 생성 교사로 사용하지 않는다. 학습·검증·평가 데이터/배치를 분리하며 Rapfi를 이겼다는 사례만으로 강화학습 수행/강한 자체 AI 완성을 주장하지 않는다.

## 평가·실험 보고

각 실험에 코드 커밋·데이터/전처리/분할 버전·시드·모델 구조/체크포인트/해시·프로필·상대 엔진 버전/모델/설정·시작 배치·흑백 배정·시간/스레드/메모리/탐색 예산·사용 장비를 기록한다. 중단/실패·완료 대국 수와 정상 보드 결과를 따로 집계한다.

평가 상대는 이전 자체 모델, 단순 기준 플레이어, Rapfi로 구분해 조건과 결과를 별도 보고한다. 이전 모델이 아직 없는 경우 부재를 기록하며 검증된 결과를 만들어내지 않는다. 같은 시작 배치에서 흑백을 교대하고 자원 프로필을 맞춰 비교한다. Rapfi는 버전/가중치/설정을 벤치마크 프로필에 고정하며 업데이트가 필요하면 새 버전의 평가 조건으로 기록해 종전 결과와 무조건 합치지 않는다. 중간 평가와 최종 보류 평가의 사용 목적도 구분한다.

| 축 | 독립 보고 항목 |
|---|---|
| 학습 성공 | 정책·가치 신경망의 학습/검증 손실·정답 지표·라벨 품질·누출/재현 검사 |
| 실력 향상 | 이전 자체 모델/단순 기준 플레이어/Rapfi를 구분한 결과·보류 배치의 흑백 교대·표본 수·무승부/오류율·불확실성 |
| 탐색 효과 | 동일 모델/배치/상대/자원에서 모델 단독 대비 변화·처리량 |

단일 상대의 소수 승률·학습 손실 감소·모의 엔진 통과를 서로의 대체 지표로 쓰지 않는다. 최종 평가 자료를 모델/하이퍼파라미터 선택에 반복 사용하지 않도록 평가 절차를 관리한다. 강한 AI의 수치 목표와 승격 기준은 데이터/상대/자원이 정해진 뒤 별도 확정한다.

## 초기 프로토콜과 최종 제출

GUI가 외부 Rapfi에 보내는 기능과 자체 엔진이 stdin/stdout에서 명령을 받는 기능을 분리한다. 본격 학습 전후 초기 단계에 최소 수신 루프/합법 응답 시험용 엔진으로 START/INFO/BEGIN/TURN/BOARD/END/ABOUT 등의 지원 범위를 확인하고 이후 모델/탐색을 연결해도 회귀한다. 시험용 고정/모의 수신기를 학습 모델·실력 완성으로 소개하지 않는다. 구현 명령/확장 목록은 기존 공식 프로토콜과 선택한 대상 버전으로 검증한다.

SWAP2BOARD는 기존 별도 호환성 요구로 추적하고 목표 리그의 의무 여부와 구분한다. 규칙 바인딩이 확인되기 전 Swap2를 렌주에 자동 연결하지 않는다. 최종 제출 연도·리그·서버 환경·모델/추론 배포 권리·패키지 크기/의존성과 공식 공고가 확인돼야 제출 검증을 완료할 수 있다. 이번에는 등록·서명·외부 업로드를 하지 않는다.
