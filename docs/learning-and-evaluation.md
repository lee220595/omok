# 학습·평가 기반의 공통 원칙과 계약 안내

2026-10-28. 최종 목표/우선순위는 [AGENTS](../AGENTS.md), 단계와 완료 기준은 [개발 계획](development-plan.md), 현재 작업/실제 검증은 [인계](handoff.md)를 따른다. 아래는 설계 계약이다. [Python 무화면 환경·자동 대국·최소 기록/재생](python-headless.md)은 구현했으며 후속 [작은 정책·가치 지도학습/체크포인트·추론 대국](supervised-learning.md)은 자체 fixture에서 기능 검증했다. 같은 모델의 [순차 PUCT/정책 비교](puct-search.md)도 기능 검증했으며 실제 기보 정제/실력 평가·RL·자체 엔진 수신·전체 평가는 미완료다.

## 공통 경계

| 영역 | 책임/상세 기준 |
|---|---|
| C++20 코어 | [상태](state-model.md) 저장, [규칙](rules-spec.md) 판정, [오프닝](opening-contract.md) 절차, [match](match-contract.md) 권한/일관된 적용. 학습/실대국이 같은 판정을 재사용 |
| 무화면 환경/기록·재생 | [환경 계약](headless-environment-contract.md)의 논리 입출력·합법 마스크·Rejected/Adjudicated·정상 종료/실행 중단·최종 결과 전파 |
| 정책·가치 모델/추론 | [공통 모델 계약](model-contract.md)의 SL/RL 재사용·관측/행동/마스크/가치·대칭·MCTS 관점·체크포인트/단계 전환 |
| 데이터 처리/자기 대국 생성 | [데이터 계약](data-contract.md)의 원본→정규화→샘플 계보·정책/가치 자격·오프닝/색 해석·분할/증강 |
| 외부 엔진/평가 실행기 | 기존 [Rapfi 어댑터](rapfi-integration.md)와 [평가 계약](evaluation-contract.md). 외부 제어와 자체 엔진 수신은 별개 |
| GUI | 수동 관찰/오류 분석·보조 복기. 미완성 편의 기능/클린 GUI 배포를 학습 착수 조건으로 두지 않음 |

C++20 기반/현재 빌드 스크립트는 유지한다. 학습은 Python 등 별도 언어가 가능하되 프레임워크/추론 도구·장비/모델 크기는 [결정 목록](requirements-pending.md)에서 검토한다. 루트 CMake는 아직 Windows x64 전용이며 코어 독립성을 Linux 학습/제출 빌드 검증으로 확대하지 않는다. 학습 의존성을 기본 GUI/C++ 빌드에 강제하지 않는다.

## 학습 경로와 공통 계약

기본 경로는 정책·가치 신경망 지도학습 → 저장 모델의 실제 합법 대국/기본 수신 응답 → MCTS → 자기 대국 경험 생성/강화학습이다. 같은 모델/입출력 계약을 재사용하고 지도학습 가중치로 RL을 시작한다. 같은 단계 재개와 다음 단계 초기화를 구분하며 optimizer 등을 무조건 함께 복원하지 않는다. 상세 복원 규칙은 모델 계약에 단일 정의한다.

AI 내부는 최소 구조부터 실험/성능 측정으로 발전시킨다. 다만 모델 입출력·체크포인트·데이터·추론 인터페이스는 SL/RL/엔진 연결에 필요한 필수 공통 계약이다. 최소 구현을 이유로 관점/버전/호환성 검사를 생략하지 않는다. 모델 블록 수·런타임을 이번 문서에서 근거 없이 고정하지 않는다.

지도학습 전처리와 자기 대국 생성은 별도 파이프라인이다. 정책 정답과 가치 정답의 자격/누락 마스크도 별도다. 정상 결과·기권·운영상 패배·불완전/미확인 결과·실행 중단을 구분하고 적격한 결과만 학습에 전달한다. 오류 대국의 추가 사용·기권/금수 등의 추가 가치 라벨은 별도 정책 버전/결정으로 관리한다.

## 프로필과 확장 원칙

현재15×15 렌주·PreparedRenju/DirectRenju/별도 Swap2 경계를 유지한다. 당시 잠정 대회 프로필과 학습/진단 실행 설정을 구분하고 수순/시간/자원을 모든 대회/학습의 상수로 고정하지 않는다. 코드의 고정200수/기존 GUI 제한은 아직 그대로이며 새로운 프로필 지원은 명시적 호환성/회귀가 필요하다.

AI 외 기능의 작은 교체 경계·버전 있는 데이터/공개 인터페이스·프로필/로그/배포·관련 회귀 기준은 개발 계획을 따른다. 미승인 규칙/보드 크기/온라인·복잡한 플러그인을 선행 구현하거나 이 원칙만으로 대규모 재작성하지 않는다.

## 평가·제출 경계

Rapfi는 현재 중간/최종 평가 전용 고정 외부 벤치마크이며 학습 상대·정답 생성 교사로 사용하지 않는다. 이전 모델/단순 기준/Rapfi/이후 다른 엔진의 역할, 개발 반복/최종 미사용 평가, 점수/오류/불확실성·자원/비결정성은 평가 계약에 단일 정의한다. 외부 엔진 대국만으로 강화학습 수행이나 강한 AI 완성을 선언하지 않는다.

프로토콜 최소 수신 검증은 초기에 시험기와 병행하고 모델/탐색 연결 후 회귀한다. 시험용 고정/단순 응답기를 학습 모델로 소개하지 않는다. 저장 모델의 합법 대국·프로토콜 응답·실력 향상·대회 적합성은 다른 완료 기준이다.

목표 연도/리그는 미정이다. 공식 공고/서버·심판·패키지/권리·CPU/메모리/GPU/시간·오프닝을 확인하기 전 제출 적합성을 완료 처리하지 않는다. 목표 리그와 무관한 GUI/Swap2 미완료는 일반 렌주 학습 개발을 자동 차단하지 않으며, 기존 별도 SWAP2BOARD 요구는 별도로 추적한다. 실제 등록·서명·외부 업로드는 별도 지시를 받는다.
