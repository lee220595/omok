# 승인 기록과 후속 확인 사항

갱신일: 2026-10-19. 파일명은 기존 링크 호환을 위해 유지한다.

## 승인 근거와 적용 범위
사용자는 대회용 규칙 설정을 기본값으로 지정하고, 이어 제시한 승인 항목 표에 대해 **“권장안 전체 승인”**이라고 답했다. 아래 결정은 확정됐으며 반복 질문하지 않는다. 이후 같은 날 **프로젝트 기반·기본 GUI 창 구현 착수**도 명시 승인했다. 현재 작업은 기반·창·빌드/실행까지이며 게임 규칙 전체·외부 AI 연동·모의 AI·자체 AI 알고리즘은 제외한다. 과거 요구사항 승인과 이번 구현 착수 승인을 구분한다.

후속 승인: 같은 날 사용자가 **게임 상태 모델과 관련 자동 테스트** 구현을 명시 승인했다. 이 후속 범위가 위 기반 단계의 제한보다 우선한다. 상태 표현·구조적 검증·CTest만 추가하며 금수·승리·200수 무승부 판정·실제 오프닝·바둑판 GUI·AI 연동·자체 알고리즘은 제외한다. 구체적인 API는 [상태 계약](state-model.md)을 따른다.

| 항목 | 확정 결정 |
|---|---|
| 장기 목표 | Gomocup 대회에 제출할 AI 엔진까지 개발 |
| 기본 규칙 | 대회용 설정 사용. 기존 Swap2 후 렌주 조합을 기본값·추가 필수 모드로 유지하지 않음 |
| 목표 대회 | 연도·리그 선정은 추후 진행. 현재 렌주 일반 대회 기준을 잠정 사용 |
| 사람 대 사람 | 한 컴퓨터에서 번갈아 착수, 온라인 제외 |

| GUI 환경·배포 | Windows 10·11 64비트, 압축 해제 후 실행 |

| 일반 착수 | 클릭 즉시 확정 |
| 기보·복기 | 첫 버전 저장·불러오기·종료 후 복기 포함 |
| 편의 기능 | 기권·재시작 포함, 무르기 제외, AI 대 AI 착수 요청 사이 관전 일시정지 |
| AI 오류 | 대회 정책 적용, 별도 재시도 제외. 실행 실패·기능 미지원은 시작 실패로 구분하며 원인·통신 기록 표시 |
| 판정 충돌 | 중단·로그 기록, 결과 미확정 |
| 연습용 제한 완화 | 현재 범위에서 제외 |
| 자체 AI 착수 순서 | 게임·외부 AI 연동 검증 완료 후 별도 단계 |

| 호환 검증 | 개발자가 실제 엔진·매니저 버전·설정·통신 로그를 확보. 모의 AI 통과만으로 제출 적합성을 주장하지 않음 |

## 승인된 잠정 작업 기준
- 15×15, RIF 기반 렌주, 전문가 준비 오프닝, 패스 금지·200수 자동 무승부.
- 현재 조사한 2026 일반 리그 기준: 한 수 30초·전체 180초, 엔진 메모리 1GB·한 CPU 코어·pondering 금지. 기본 시간은 사람·AI 모두 사용한다.
- 목표 연도·리그가 정해지면 해당 공식 공고로 갱신한다. 지금의 잠정 기준 승인이 특정 참가 연도·리그 선정이나 심판 구현 검증 완료를 의미하지 않는다.
- SWAP2BOARD 지원 요구는 유지하지만 기본 오프닝과 분리한다. Swap2 GUI의 임시 배치·확정 방식은 직전 승인 표에서 추후 항목으로 안내했으므로 이번 전체 승인으로 확정하지 않는다.

## 후속 선정·조사 사항
| 사항 | 다음 처리 | 상태 |
|---|---|---|
| 목표 연도·리그 | 참가 계획을 정할 때 사용자와 선정 | 추후 결정하기로 승인, 지금 답변 불필요 |
| 매니저·버전·연결 방식 | Piskvork 우선 조사, GomocupJudge 비교; 역할·지원·라이선스 근거를 갖춰 제안 | [후보 조사](integration-candidates.md) 작성. 실제 채택·연동 검증은 미완료 |
| 렌주 세부 판정 | RIF 9.1~9.3과 고정 GomocupJudge 대조 | 2026-10-23 명세·구현·사례 대조 완료. 전체 배치·최종 운영 심판 호환성은 미검증. [계약](rules-spec.md) |
| 수순 제한 경계 | 준비 배치 포함 총 200수, 200번째 승패·금수 우선 | 고정 심판 소스·원본 루프 실행으로 확인. 준비 복원·종료 차단도 후속 오프닝 단계에서 검증 |
| 시간·자원·오류 처리 | 초기화 시간 계측, 종료·잘못된 응답·불법 수의 대회 처리, 제한 강제 방법 확인 | 개발자 기술 조사 |
| 실제 엔진 검증 대상 | 버전·지원 규칙·사용 조건 확인. 재배포 필요 시 별도 라이선스 확인 | 개발자가 선정·검증, 현재 실행 검증 없음 |
| Swap2 상세 화면 | 해당 오프닝을 사용하는 GUI 경로가 필요할 때 제품 동작 확인 | 현재 기본 오프닝에는 해당 없음 |

제품 동작이나 범위가 달라지는 새 선택은 근거와 대안을 갖춰 사용자에게 확인한다. C++ 표준·GUI 라이브러리·빌드 시스템·기보 형식·비동기 처리·검증 도구 등 승인 범위 안의 기술 선택은 개발자가 결정하며 매번 재승인받지 않는다.

## 이전 질문 정리
- 기존 규칙·무승부·시간·승리 주장 질문(1~3·5·18·19)은 대회 기준 조사로 대체됐다. 만판만·무제한 수순, 사람 무제한·AI 10초/5분, 기존 결합 규칙 공존 권장안은 철회됐다.
- 사람 대 사람·매니저 역할·환경·배포·화면·기보·편의 기능·충돌·자체 AI 순서·제출 범위·연습 설정 질문은 위 승인 표로 해결됐다.
- AI 오류의 최종 승인안은 대회 정책 적용이다. 이전의 일괄 패배 권장안이나 임의 재시도를 독립된 제품 정책으로 되살리지 않는다.
- 기존 매니저 활용 요구는 유지한다. 검증용 활용 허용은 기존 매니저를 전혀 쓰지 않아도 된다는 뜻이 아니다.

## 2026-10-23 추가 구현 승인

사용자가 상태 모델 재검토와 렌주 명세·판정 모듈·관련 자동 테스트·심판 조사/대조를 승인했다. 상태 저장 계약은 유지하고 판정은 rules로 분리했다. 실제 오프닝 진행·바둑판 GUI·AI 통신/프로세스·자체 AI는 이번 승인 범위 밖이다. 공식 기준과 비교 심판 선정은 기술 조사로 진행했으며 최종 참가 연도·리그는 미정으로 유지한다. 확인한 사례에 구현을 막는 규칙 충돌은 발견하지 않았다.

같은 날 후속 요청으로 준비 배치 복원·본게임 인계·독립 Swap2 상태 전환·조사·자동 테스트를 승인했다. 준비 로더와 자체 테스트 배치를 구현했지만 공식 렌주 데이터·재배포 권한은 미확보다. Swap2의 규칙 바인딩은 미해결로 유지하고 완료 후 일반 대국을 차단한다. 상태의 배치 주체를 optional로 확장해 외부 준비 돌과 실제 A/B를 구분했다. 제품 기본값에 렌주+Swap2 조합을 추가하지 않았다. [오프닝 계약](opening-contract.md)·[검증](verification-opening.md)을 따른다.

## 로컬 대국 구현·검증 재개 승인 (2026-10-24)

사용자는 match·로컬 사람 대 사람 Win32 보드·기권/재시작·비동기 금수 표시·관련 테스트를 승인했고, 후속 요청으로 WIP 소스 보존과 수동 GUI 검증 재개를 명시 승인했다. 이번에는 AI·Swap2 GUI/규칙 연결·대회 시계/자원·기보 파일/복기로 확대하지 않는다. GUI 도구가 작동하지 않으면 독립적인 코드·자동 검증·원격 저장을 완료하되 구체적 수동 절차를 남기고 단계 전체 완료로 표시하지 않는다. [최신 검증](verification-match.md)을 따른다.

## 외부 Rapfi 초기 연결 승인 (2026-10-24)

사용자는 external/rapfi에 압축 해제한 Rapfi를 조사하고 기존15×15 렌주/준비 배치를 유지해 별도 프로세스와 Gomocup/Piskvork 통신·응답 검증·시간/오류/이전 응답 차단을 구현한 뒤 GUI 사람 대 Rapfi로 연결하도록 승인했다. 바이너리/가중치는 Git 제외하며 자체 AI 개발로 확대하지 않는다. 이번에는 AI 대 AI·Swap2 연결·기보·사람 시계를 추가하지 않았다. 일반 기술 선택으로 매 요청 새 프로세스/전체BOARD 복원을 채택했으며 성능 제약을 기록했다. [계약](rapfi-integration.md)·[검증](verification-rapfi.md)을 따른다.
