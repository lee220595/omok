# 보상·학습 목표 변환 계약

2026-10-29 설계 v1. 규칙 심판과 [학습·성능 감시자](monitoring-contract.md)에서 보상 계산을 분리한다. **RL 경험 생성/업데이트·RL 재개는 미구현**이며 이번에는 코드/학습을 실행하지 않는다. SL의 실제 data.value_target과 checkpoint.initialize_for_rl은 재사용하되 RL 루프가 구현된 것으로 소개하지 않는다.

## 판정·결과 매핑·자격·업데이트 분리

1. C++ 규칙/대국 제어는 실제 합법성·승패/종료 사유를 판정/적용한다([환경 계약](headless-environment-contract.md)).
2. 보상 계산기는 그 결과를 저장된 착수 전 actor 관점의 결과 점수로 매핑하고 데이터/보상 정책의 자격을 확인한다.
3. 자격을 만족한 국면에만 정책/가치 목표를 만든다. 학습기는 목표로 모델을 업데이트하고 감시자는 이 과정을 관찰한다. 실행 중 감시자가 보상·학습률을 변경하지 않는다.

초기 권장 결과 매핑은 **승리+1, 패배/규칙상 금수패-1, 규칙상 무승부0**이다. 금수패의 승리 상대는+1이다. 이는 결과의 의미이며 모든 결과를 학습에 넣는다는 승인이 아니다. 금수 방지는 우선 합법 수 마스킹으로 하고 -100 같은 임의 벌점을 기본값으로 확정하지 않는다. shaping·할인·중간 벌점은 별도 버전/실험 결정이 필요하다.

가치 목표 z_t는 저장된 국면의 현재 차례 actor가 최종 승자이면+1, 패자이면-1, 적격 무승부이면0이다. 최종 next_actor는 지워질 수 있으므로 저장된 actor/색 배정을 사용하며 흑 고정 관점·수순 홀짝으로 추정하지 않는다. PUCT의 leaf/backup 관점은 [모델 계약](model-contract.md)·[실제 PUCT](puct-search.md)를 따른다.

| 실제 사건 | 결과 보존/초기 권장 매핑 | 현재 학습 자격과 후속 조건 |
|---|---|---|
| 보드 승패·규칙200수/만판 무승부 | 승/패±1, draw0 | 기존 board-outcome-v1 가치 자격 사용. 준비 배치도 수순에 포함 |
| 규칙상 금수패 | 시도 돌/성공 이력 불변, 반칙패·종료 이벤트/버전 변경. 결과상 금수 actor-1/상대+1 | **현재 board-outcome-v1/value_target은 가치 None/보류**. 반칙 시도는 SL 다음 수 정답이 아님. 마스킹 후 발생한 구현 오류는 실행/trajectory 격리가 우선 |
| 확인된 기권/합의 등 | 확인된 결과와 사유를 유지 | 현재 가치 보류 정책 유지. 별도 허용 정책/신뢰도 기준 전 자동 포함 금지 |
| 형식/Token/권한 거부 | 전체 상태 보존, 정상 착수/결과 점수 없음 | 정상 전이/목표로 만들지 않음. 동작 검증용 부정 시험과 실제 실행 오류 구분 |
| 오류·시간 초과·취소·blocked/aborted·임의 cap | 판정된 대회 결과가 있으면 사유와 함께 보존, 없으면 미확정 | 기본 정상 학습/정상 보드 WDL 제외. 숫자0으로 누락을 채우지 않음. 대회 판정 점수는 [평가 계약](evaluation-contract.md)의 별도 집계 |

초기 매핑 권장과 현재 라벨 자격의 차이는 의도적이다. 금수패를 RL 가치에 포함하려면 사전에 새 라벨/보상 프로필 ID·대상 trajectory/원인·가중치·오류 격리 기준을 정하고 [데이터 계약](data-contract.md)·metadata/테스트를 함께 갱신한다. 이번 문서로 기존 SL 전처리/샘플 의미를 바꾸거나 금수패-1을 이미 학습한다고 기록하지 않는다. 합법 수0은 규칙 결론 미정으로 보류하며 패스·draw·패배를 만들지 않는다.

## 후속 RL 연결 조건 — 구현 아님

- 같은 정책·가치 모델을 사용한다. SL→RL 첫 시작은 initialize_for_rl의 가중치 로드/optimizer 기본 초기화 의미를 재사용한다. 보존 실험은 명시적으로 기록한다. 현재 함수는 초기 가중치를 제공할 뿐 RL 데이터/optimizer update/재개를 수행하지 않는다.
- RL 같은 단계 재개는 별도 stage/kind/schema·optimizer/scheduler/RNG·완료 step/모델·경험/분할/완료 대국 목록·보상 프로필을 복원한다. 현재 SL 전용 loader가 RL 체크포인트를 지원한다고 가정하거나 SL 초기화 함수를 RL 재개로 쓰지 않는다.
- 현재 순차 PUCT의 성공한 검색에서 `pi_t[a]=root_visits[a]/S`를 초기 정책 목표 후보로 한다. S는 root expansion을 제외한 완료 simulation 수다. 현재 실제 필드/통계 정의는 PUCT 문서를 재사용한다. 방문0인 합법 행동의 목표0은 허용하되 전체 합법 후보를 임의 제거하지 않는다.
- 원본 스냅샷 ID/Token·actor·프로필·합법 mask에 해당하는225개 유한 비음수 분포, 합1·불법 질량0·방문/예산 정합을 검증한 뒤만 편입한다. 실패한 검색의 부분 분포를 정상 pi로 쓰지 않는다. 선택 action 하나와 정책 목표 분포를 구분하고 정책/가치별 자격을 기록한다.
- 적격 정상 종료 결과를 각 국면 actor에 전달해 z_t로 사용한다. 중단/손상/오류 trajectory를 draw0으로 채우지 않으며 탐색 leaf v나 선택 edge Q를 최종 정답 z로 바꾸지 않는다. 금수/기권 추가 편입은 위 별도 정책 결정 전 보류한다.
- 기존 SL batch는 action/distribution target을 표현하지만 현재 추출기는 일반 action 정답만 생성한다. 저장 방문 분포를 검증/경험화하는 생성기와 RL 업데이트·재개는 아직 없다. 기존 trace/독립 재생/완료 단위 재개를 재사용하며 재생만으로 탐색 메타데이터의 진위를 확정하지 않는다.
- 루트 노이즈·온도/탐험·경험 재사용·모델 갱신 주기·손실 가중/승격 기준은 RL 실행 전 명시적으로 결정한다. 현재 결정적 순차 PUCT 대국이 탐험적 자기 대국 학습을 완료한 것은 아니다. Rapfi는 계속 평가 전용이다.

## 후속 수용 검증

현재 actor 양쪽의 승/패·규칙 draw와 금수패 매핑/자격 보류를 분리해 시험한다. 금수/기권 행동의 정책 제외, cap/오류/blocked의 목표 부재, 준비 배치 포함200수·정확한 흑5목/금수 우선, 올바른 방문 분포의 편입·변조/부분 분포 거부를 확인한다. SL 초기화와 같은 RL 단계 재개의 모델/optimizer/RNG/경험 복원 범위를 별도로 검증한다. 합법 대국/감시 검사 통과를 RL 업데이트·실력 향상 완료로 보고하지 않는다.
