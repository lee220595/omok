# 호환성 1차 조사

초기 조사일: 2026-10-19. 이 문서의 초기 조사에서는 문서 확인만 수행했다. 이후 같은 날 기반·기본 GUI 구현을 승인받아 개발을 시작했다. 후속 후보 소스·라이선스·버전 조사는 [매니저·엔진 후보](integration-candidates.md), 자체 기본 창의 실제 빌드·실행은 [기반 검증 기록](verification-foundation.md)을 따른다. 외부 매니저·AI 엔진은 아직 실행하지 않았다.

같은 날 사용자 변경 지시로 **대회용 규칙 설정을 기본값**으로 채택했다. 종전 Swap2 후 렌주 조합 유지 방침은 철회했다. 참가 연도·리그는 미정이며, 기존 렌주 논의에 따라 Gomocup 렌주 일반 대회 기준을 잠정 작업값으로 사용한다. 추가 리그나 기존 조합 모드를 자동으로 구현하지 않는다.

이후 같은 날 사용자가 권장안을 전체 승인했다. 외부 AI 검증용 매니저 활용, 후보 조사 후 제안, 판정 충돌 시 중단·로그 기록·결과 미확정, 대회 오류 정책 적용과 별도 재시도 제외가 확정됐다. 이는 매니저 채택·연동·실제 엔진 검증의 완료나 구현 착수를 뜻하지 않는다. [전체 결정 기록](requirements-pending.md)을 따른다.

## 확인 내용과 프로젝트 영향
- 프로토콜 문서는 표준 입출력 파이프와 기본 명령을 정의하며 `SWAP2BOARD` 확장을 포함한다. 확장 지원 여부는 엔진마다 확인해야 한다. 미지원 엔진에서 다른 오프닝으로 자동 대체하지 않는다.
- 프로토콜 호환은 전송·응답 형식의 호환이다. 보드 크기·오프닝·판정·시간·대회 참가 조건의 일치까지 의미하지 않는다. 현재 기본값은 대회용이며 잠정 렌주 기준이다. Standard 등 다른 리그를 임의로 선정하지 않는다.
- RIF 규칙은 금수의 예외·승리 우선관계를 포함한다. 단순 문자열 패턴 수 계산만으로 판정이 충분하다고 가정하지 않는다. RIF 자체 오프닝·승리 주장·무승부 절차를 일괄 도입하지 말고 Gomocup의 수정 규정과 대상 심판을 대조한다.
- 프로토콜의 BOARD는 엔진 기준 자신의 돌/상대 돌을 사용하고 렌주는 착수 순서 보존을 요구한다. Swap2 이후 색 대응과 전체 배치 복원을 함께 검증해야 한다.
- SWAP2BOARD의 입력은 0·3·5개 좌표에 따라 달라진다. 응답은 단계에 따라 3돌, SWAP, 1돌 또는 2돌이므로 하나의 일반 착수 파서로 처리하지 않는다. 색 선택과 함께 4·6번째 착수가 응답되는 경로도 검증한다.
- 시간 값의 프로토콜 의미를 제품 UI와 혼동하지 않는다. 특히 `timeout_turn=0`은 무제한이 아니다. 제품의 무제한 설정을 그대로 0으로 전달하지 않는다.

초기 조사에서는 Piskvork 라이선스 본문을 확보하지 못했으나 후속 조사에서 제작자 문서와 protocol.cpp의 GPL-3.0-or-later 표기를 확인했다. 2026-10-23에는 GomocupJudge `client/check_forbid.py` 헤더의 GPL-3.0-or-later도 확인했다. 저장소 전체와 다른 파일의 조건까지 일괄 확정한 것은 아니다. 상세 근거는 후속 후보 문서를 따른다. 소스 공개를 무조건적인 수정·재배포 허가로 해석하지 않는다. 전체 매니저/엔진 연동은 미검증이다.

## 다음 검증과 대안
1. 지정 매니저 없이 후보 검증 후 제안하는 절차와 검증용 활용 허용은 승인됐다. Piskvork부터 조사하고 GomocupJudge와 비교한다.
2. 후보의 버전/커밋을 고정해 규칙 구현, GUI 연결 지점, 엔진 실행·시간·종료 제어, 라이선스 원문·배포 의무를 확인한다.
3. 구현 단계 진입 후 기본 대회 설정의 준비 오프닝·규칙·시간·수순 제한으로 최소 연동 검증을 수행한다. 요구된 Swap2 통신 경로는 별도 검증한다. 판정 충돌 시 승인된 중단·로그 기록·결과 미확정 정책을 적용한다.
4. 외부 GUI 인터페이스가 있으면 어댑터 연결을 우선 검토한다. 없으면 허용된 라이선스 범위에서 연결부 수정, 또는 승인된 기존 매니저의 외부 AI 검증용 활용을 검토한다. 구체적인 버전·역할·연결 방식을 증거와 함께 제시한다.
5. 어느 활용 방식도 성립하지 않으면 다른 기존 매니저 후보를 조사한다. 필수 요구를 조용히 포기하거나 규칙을 바꾸지 않는다. 승인 범위 안의 기술 선택을 반복 승인 대상으로 만들지 않는다.

통신 규격 지원, 대상 대회 설정 지원, 외부 GUI 연결, 프로세스 관리, 배포 허용을 각각 증거와 검증 상태로 관리한다. 문서 확인을 실행 검증 완료로 표시하지 않는다.

## 장기 목표: Gomocup 제출 엔진 — 추가 조사

2026-10-19 사용자 확인으로 장기 목표에 대회 제출용 AI 엔진이 포함됐다. 현재 단계의 알고리즘 개발은 시작하지 않는다. 대회용 기본값은 승인됐으며 아래의 2026 자료는 잠정 설정의 근거로 사용한다. 목표 연도·리그 선정까지 확정된 것은 아니다.

추가 근거:
- [Gomocup 2026 공고](https://gomocup.org/news/gomocup-2026-announcement/)
- [공고에서 연결한 Swap2 설명](https://www.renju.net/rule/11/)
- [일반 대회·실행 규정](https://gomocup.org/detail-information/)
- [제출 절차·포장·일반 오류](https://gomocup.org/enroll/)

### 규칙과 대회 선택
- 공식 일반 안내의 렌주 대회는 전문가가 준비한 오프닝을 쓰며 26형에 한정하지 않는다. 패스를 허용하지 않고 200수 후 자동 무승부로 설명한다. 이는 Swap2 후 렌주 게임과 동일하다고 볼 수 없다.
- 2026 공고의 무제한 대회는 Swap2를 명시한다. 연결된 설명은 Gomoku 오프닝이다. 이 공고만으로 Swap2 후 렌주가 공식 참가 규칙이라고 해석하지 않는다.
- 목표 연도·리그를 정한 뒤 규칙·오프닝·판 크기·시간·수순 제한을 각각 확인하고 기본값을 갱신한다. 기존 게임 조합과 대회 설정을 공존시키자는 제안은 사용자가 거절했으므로 재질문하거나 필수 범위로 남기지 않는다.

### 엔진 제출·배포
- 제출 안내는 엔진과 필수 파일을 ZIP으로 포장하고 매니저에서 직접 로드할 수 있게 요구한다. 엔진 실행 파일의 pbrain- 접두사와 ZIP 루트 위치를 확인한다. 게임 GUI 이름에는 적용하지 않는다.
- 깨끗한 Windows에서 동작하도록 필요한 DLL을 포함하거나 적절히 정적 링크한다. 제출 양식의 저작권 진술과 사용자 사이트 제출 절차가 있다. 외부 엔진을 연결한 GUI나 모의 AI의 완성을 자체 AI 제출 완료로 취급하지 않는다.
- 2026 공고는 규칙·판 크기별 여러 실행 파일의 접미사 규약도 허용한다. 현재의 15×15 전용 게임을 이유 없이 20×20으로 확장하지 않는다.

### 자원과 환경 — 2026 참고값
- 공고 기준 메모리 1GB, AI 크기 제한 256MB. 시간은 fastgame 한 수/전체 5초/120초, final leagues 300초/1000초, 나머지 30초/180초다. 현재 잠정 일반 리그 기본값은 30초/180초를 사용하며 종전 사람 무제한·AI 10초/5분 권장안은 철회한다.
- Windows 10·11 및 명시한 대응 서버 환경, 사전 의존성이 없는 실행, CPU 명령어 호환 조건을 확인해야 한다.
- 일반 안내에는 한 CPU 코어 제한, pondering 금지, 엔진 화면 표시·네트워크 통신 금지 및 임시/영구 파일 관련 제한이 있다. 무제한 대회는 하드웨어·포장·실행 절차가 다르므로 일반 리그 조건을 그대로 적용하지 않는다.
- 2026 대회 일정은 이미 지났다. 다음 참가 연도의 공고를 다시 확인한다. 미래 연도 규정을 현재 수치로 추정하지 않는다.

### 개발자가 후속 조사할 기술 항목
- START/INFO/BOARD/SWAP2BOARD와 엔진별 지원 확인, 렌주 색 인식·순서 복원, 초기화 시간·전체 시간 계측, 종료 처리와 과다 출력 방어.
- 선택 매니저·심판 버전에서 200수 경계와 동시 승리/금수 우선순위, 시간·메모리·프로세스 제한 실제 처리 확인.
- 실제 엔진·매니저의 버전, 규칙 설정, 입출력 로그와 결과를 남기는 회귀 검증 계획. 자동 테스트가 운영진의 참가 승인을 보장하지는 않는다.
- 자체 AI 단계 전 외부 코드·모델·엔진의 저작권과 제출 진술 적합성을 확인한다. 제출용 알고리즘·학습 방식은 현재 결정하거나 구현하지 않는다.

## 2026-10-23 규칙 구현을 위한 후속 검증

비교 심판으로 기존 조사 커밋의 GomocupJudge `56cfd7dc1a0d1ec06d29f44a26931f375ad05991`을 선정했다. 공식 RIF 문서와 일반 대회 안내를 다시 확인했고, `check_forbid.py`·`ai_match.py`의 원본 함수·대국 루프를 실제 실행했다. 준비 배치를 포함한 200수·마지막 수의 승패 우선순위를 확인했다. 자체 CTest, 실제 판정 함수 실행, 전체 매니저/엔진 대국은 서로 다른 검증이다. 후자는 여전히 미실행이다.

[규칙 명세](rules-spec.md)·[사례](renju-cases.md)·[검증 기록](verification-rules.md)에 버전·해시·정확한 명령·출력·한계를 기록했다. 최종 참가 연도·리그나 공식 운영 심판의 버전은 미정이며, 이 비교 버전 선정을 그 승인으로 해석하지 않는다. 대상 심판과 불일치 시 기존의 중단·로그·승패 미확정 정책을 유지한다.

## 후속 오프닝 조사·구현

같은 고정 커밋의 server/server.py·client/utility.py·ai_match.py·doc/GomocupProtocol.md를 확인했다. 서버 준비 파일은 중심 상대 x,y 쌍, client 전달은 문자 x·1 기반 숫자 y의 compact 수순이다. 준비 배치의 순서·교대·전체 수순 계산과 SWAP2BOARD 0/3/5돌 선택 경로를 문서화했다. 제품 로더는 compact의 엄격한 15×15 부분집합만 구현하며 서버 파일·프로토콜 문자열 파서는 아니다.

고정 트리에서 확인한 openings_20.txt를 렌주 공식 데이터로 채택하지 않았다. 공식 렌주 데이터·재배포 권한이 없어 사용자 승인된 대안인 자체 작성 배치와 로더로 검증했다. 데이터·원본 소스는 제품에 동봉하지 않는다. [출처·규칙 분리 계약](opening-contract.md)과 [실제 비교 기록](verification-opening.md)을 따른다.

원본 초기화는 준비 배치를 판정 없이 신뢰하므로 프로젝트의 금수 데이터 거부·종료 차단을 심판과 동일하다고 보고하지 않는다. 유효 입력만 원본 초기화·좌표 변환·Swap2 네 경로로 실행 대조했다. Swap2 실행은 고정 응답 도구이며 실제 엔진/통신을 사용하지 않았다. 절차 지원과 렌주 규칙 결합을 구분하며 최종 규칙 바인딩은 미해결로 남긴다.
