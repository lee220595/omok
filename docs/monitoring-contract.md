# 규칙 심판·학습/성능 감시 계약

2026-10-29 설계 v1. **감시자 실행기·heartbeat·자동 승격/중단 연결은 미구현**이다. 코드 기준 `2dc4eab`의 기존 검사와 순차 실행을 재사용하는 계약이며 새 API/명령이 아니다. 이번에는 문서만 수정하며 RL 업데이트·학습·평가는 실행하지 않는다. [현재 인계](handoff.md)와 [개발 계획](development-plan.md)을 따른다.

## 책임과 기존 구현의 재사용

두 감시자는 책임 구분이며 AI 모델 두 개나 별도 서비스 두 개가 아니다. 초기 구현은 순차 실행기에서 호출하는 작은 검사/이벤트 집계 경계로 한다. 상태의 단일 작성자를 유지하고 감독을 이유로 병렬 실행·분산 큐·플러그인 체계를 먼저 만들지 않는다.

| 책임 | 재사용 지점 | 부족한 부분/이번 설계 |
|---|---|---|
| A. 게임 규칙 심판 | C++ rules::evaluate·match::Controller::place, src/headless/bridge.cpp의 omok_mask, Python Environment의 snapshot/mask/step/clone | 같은 환경/Token의 관측→마스크→행동을 묶은 감사 이벤트. Python에 금수/승패를 복제하지 않음 |
| B. 학습·성능 감시자 | checkpoint.load, checked_outputs/masked_logits, train.metrics, ModelPlayer·PUCT의 상태/출력 검사, runner·records.replay·compare_search | 지표 수집/판정·heartbeat/진행 구분·전술 세트·통계적 승격 관문·감시 증거/중단 요청 |
| 보상 계산기 | data.value_target의 board-outcome-v1, MCTS의 현재 actor 관점/terminal_value | [보상 계약](reward-contract.md)의 자격 확인/목표 변환. 감시자와 분리하며 RL 업데이트는 아직 없음 |

A는 매 실제 착수의 합법성·금수·승패·종료를 기존 코어로 확인한다. B는 A의 이벤트와 학습/평가 지표를 관찰할 뿐 판정·수순·학습 목표를 수정하지 않는다. 보상 계산기는 판정 결과와 별도 자격 정책을 입력으로 받는다. 어느 감시자도 실행 도중 보상·학습률·탐색량·규칙을 임의 변경하거나 누락된 값을 정상값으로 채우지 않는다.

현재 있는 검사와 없는 기능을 구분한다. train은 출력/손실 유한성을 검사하고 epoch별 metrics를 기록하지만 heartbeat·gradient/optimizer 종합 감시·진행 정체 분류는 없다. ModelPlayer는 모델 해시/계약·형상/유한성·Token을 검사하지만 마스킹 전 불법 확률 질량은 저장하지 않는다. records.replay는 수순/보드/결과를 검증하며 탐색 메타데이터 전체를 검증하지 않는다. compare_search는 일부 root 예산을 검사하지만 일반 전술 실행기·통계 승격 감시자는 아니다.

## A의 불변조건과 독립적인 정답

- 관측·마스크·선택 행동은 같은 Environment ID/스냅샷 Token·규칙 프로필·현재 actor에 대응해야 한다. clone의 Token은 원본과 같다고 가정하지 않으며 논리 상태/계보로 연결한다. 적용 직전 최신 Token으로 코어가 다시 판정한다.
- 정상 SL/추론/PUCT는 기존 합법 마스크를 사용한다. 빈칸만 검사하거나 금수 판정을 Python에 재구현하지 않는다. 정확한 흑5목 우선, 준비 포함200수·최종 수의 승리/금수 우선은 [규칙](rules-spec.md)·[환경](headless-environment-contract.md)을 유지한다.
- 진단용 마스킹 전 불법 질량은 유한한 logits의 전체225개 softmax를 p_raw로 두고 `sum(p_raw[a] for mask[a]==False)`로 정의한다. 마스킹 후 실제 불법 선택 횟수와 별도 지표다. 전자는 모델 경향이며 반칙패나 즉시 실행 실패가 아니다. 현재는 미수집이며 운영 임계값도 미정이다.
- 마스킹 후 불법 질량/선택은 구현 오류로 조사한다. 좌표/행동 변환·다른 상태의 마스크·stale 결과·마스크 적용 누락·부정확한 규칙을 구분해 증거를 남긴다. 엔진의 실제 불법 수 결과와 학습 자격을 혼합하지 않는다.
- 금수는 시도 돌을 보드/성공 이력에 넣지 않되 반칙패·종료 이벤트·revision을 갱신한다. 형식/권한/Token/점유 오류로 거부한 요청은 전체 상태를 보존한다. 종료 후 요청도 거부하며 종료 결과를 바꾸지 않는다.
- playing에서 합법 수0은 blocked로 격리한다. 실행기의 aborted/취소/길이 cap을 패스·draw·패배로 변환하지 않는다.
- 같은 코어의 출력을 그대로 정답으로 복사하면 공통 결함을 잡지 못한다. 검토된 [렌주 사례](renju-cases.md)·[기존 규칙 대조 근거](verification-rules.md)·tests/fixtures/renju.tsv와 상태/규칙/오프닝/match 회귀를 우선 사용한다. Python 마스크와 실제 적용의 일치는 연결 검증이고 독립적인 규칙 정확성의 증명은 아니다. 불일치 시 정답 근거부터 검토하고 승인 없이 규칙을 고치지 않는다.

## B의 판정 상태·적용 범위·기본 대응

| 상태 | 의미 | 기본 대응 |
|---|---|---|
| 정상 | 실행한 해당 검사/선언된 예산에서 불변조건 또는 사전 기준 충족 | 증거 기록. 실행하지 않은 검사/강함/대회 적합성까지 정상으로 확대하지 않음 |
| 주의 | 정체/망각/과적합/지연 등 의심이 있으나 원인·표본이 부족 | 경고·원인 조사, 이미 정한 평가 예산 안의 관측 지속. 자동 하이퍼파라미터 변경 금지 |
| 실패 | 계약/유한성/규칙 정답/기록 무결성의 명백한 위반, 또는 사전 확정한 필수 관문 실패 | 해당 실행/대국/샘플/체크포인트 격리·승격 차단·안전한 중단 요청. 알려진 정상 결과를 덮지 않음 |
| 판단 보류 | 표본·필수 증거·측정 임계값 부재, 중단/blocked 등 정상 성능 판정 불가 | 이유/추가 조건 기록. 승격에 필요한 판정이면 승인하지 않되 패배나 실패율0으로 채우지 않음 |

승격은 다음 학습/평가의 기준 모델로 채택하는 절차이며 현재 자동 승격 기능은 없다. 실패의 범위는 원인이 있는 대상에 한정한다. 공유 규칙/DLL 결함이면 그 버전을 쓴 자료의 영향 범위를 추적해 함께 격리한다. 취소 자체를 학습 실패로, 성능 정체 의심을 규칙 오류로 분류하지 않는다.

초기 자동 대응 한도는 기록·경고·실패 격리·승격 차단·안전한 중단 **요청**이다. 소스/모델/기보 자동 수정, 강제 프로세스 종료, 임의 재시작/재학습·보상/학습률 조절은 하지 않는다. 중단 요청은 실행기가 수신/확인/저장 완료했는지 별도 상태로 기록한다. 현재는 요청 수신 hook이 없으므로 이미 구현된 기능으로 안내하지 않는다. 대국은 완료 단위, SL은 마지막 저장 완료 epoch를 복구 기준으로 하며 미완료 부분을 완료로 승격하지 않는다. 멈춘 프로세스가 응답하지 않으면 미확인 중단으로 보고하고 직접 조작 여부를 사용자에게 맡긴다.

## 감시 이벤트와 임계값의 종류

미래 감시 이벤트의 논리 필드: schema·규칙 ID/버전·검사 구현/설정 해시·run/attempt ID·이벤트 순번·UTC 시각과 프로세스 내 monotonic 경과·단계·대상 ID/Token·입력/결과 지표·판정 상태/영향 범위·요청/확인한 대응·증거 경로/해시. 기존 trace/manifest를 연결하고 전체 모델/보드를 매 이벤트 복제하지 않는다. 비밀정보나 대용량 원시 자료를 Git에 넣지 않는다. 이벤트 재수신은 `(run,attempt,sequence,rule_version)`로 중복 방지하도록 설계하며 대국 점수 집계 ID와는 구분한다.

아래 규칙은 v1 설계다. **확정 불변조건**은 NaN/Inf 금지·형상/계약 일치·stale 거부/상태 보존·마스크와 적용 정합·검토된 fixture 정답·동일 평가 중복 금지다. 정규화 허용 오차는 기존 검사값/버전을 추적한다(PUCT는 현재1e-5). 새 운영 임계값을 여기서 발명하지 않는다.

heartbeat 간격/허용 지연, 단계별 진행 timeout/연속 정체 창, 지연/처리량 하락 비율, 망각/과적합 허용 폭·대국 최소 표본/효과 크기/승격 기준은 **측정 후 실행 전 결정할 값**이다. 현재 자동 기준은 비활성/판단 보류다. 예시로 ‘주기 h의 k배 지연’을 쓸 수 있으나 h/k 숫자는 운영 기본값이 아니다. 설정 미정이라고 유한성/권한 등의 확정 검사를 끄지 않는다.

LP-03의 실제 진행은 단계에 맞게 본다. 학습은 완료 update/step와 저장 epoch, 자기 대국은 완료 simulation/착수/대국, 평가/저장은 해당 작업 진척을 사용하도록 설계한다. 평가 중 optimizer step이 늘지 않거나 완료 대기 중인 것은 학습 정체가 아니다. 프로세스가 살아 있다는 사실/주기 로그만으로 실제 진척을 증명하지 않는다. 현재 epoch metrics만으로 batch 단위 정체를 검출했다고 주장하지 않는다.

## 구현 순서와 수용 기준

다음 최소 구현 제안은 **기존 검사 결과를 작은 공통 이벤트/보고로 연결하는 순차 감시 경계**다. RL 업데이트나 새 학습은 포함하지 않는다. 먼저 고정 fixture·가짜 시계/지표·기존 저장 기록으로 위 규칙의 정상/주의/실패/보류와 격리 범위를 검증하고, 실제 runner/모델/PUCT 검사에 중복 없이 연결한다. heartbeat producer/중단 수신은 미지원이면 그 사실을 보고한다. 운영 임계값 활성화와 실제 학습/RL 연결은 별도 승인/측정 뒤 진행한다.

완료 기준은 모든 규칙의 재현 가능한 오류 주입/정상 대조, 금수패/구조 거부/중단 자격의 구분, 고정 checkpoint/평가 ID 중복 방지·완료 단위 재개, 기존 회귀 유지, 증거와 대응 요청/확인의 기록이다. 감시자 코드/새 테스트·새 명령은 이번에 만들지 않았다. 상세 평가·전술/예산·탐색 통계는 [평가 계약](evaluation-contract.md), 목표/자격은 보상·데이터 계약을 단일 기준으로 사용한다.
