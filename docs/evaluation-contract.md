# 외부 벤치마크·실력·제출 평가 계약

2026-10-28 설계. **범용 평가 실행기·아래 통계/프로필 전환 기능은 미구현**이다. 현재 고정 simulation의 [PUCT/정책 단독 소규모 개발 비교](puct-search.md)는 구현했다. 동일 시간/범용 외부 평가·아래 통계 프로필 전체는 미구현이며 기존 Rapfi probe/GUI 검증을 반복 평가 완료로 보지 않는다. [Rapfi 어댑터](rapfi-integration.md)의 실제 통신/자원/오류 정책과 [환경 사건 구분](headless-environment-contract.md)을 재사용한다.

## 평가 상대와 데이터의 역할

| 대상 | 역할 |
|---|---|
| 이전 자체 모델 | 회귀/승격·학습 전후 비교. 코드/체크포인트·추론/MCTS 조건 고정 |
| 단순 기준 플레이어 | 합법성/파이프라인·기본 성능 진단. 모의/단순 수 선택기를 강한 자체 AI로 소개하지 않음 |
| Rapfi | **중간·최종 평가용 고정 외부 벤치마크**. 현재 학습 상대·정답 생성 교사로 사용하지 않으며 결과/기보를 학습 경험/정답으로 전용하지 않음 |
| 이후 다른 엔진 | 상대 다양성/일반화 검증용 별도 벤치마크 후보. 선정/권리/규칙/프로필 검증 후 추가, Rapfi/이전 모델 결과와 임의 합산하지 않음 |

상대가 아직 없으면 부재/미검증을 기록한다. Rapfi의 실행 파일·모델/가중치 해시·config·버전·CPU용 빌드를 벤치마크 프로필에 고정한다. 바꾸면 새 프로필이며 기존과 조건이 같다고 가정하지 않는다. 기존 사람 대 Rapfi는 수동 관찰/디버깅용으로 유지한다.

학습·검증·평가 데이터/시작 배치·상대 계보를 구분한다. 개발 중 반복 확인하고 모델/하이퍼파라미터를 고르는 평가는 **개발 평가**다. 최종 미사용 배치/설정/상대 조건은 후보 모델/설정과 평가 절차를 고정한 뒤 사용한다. 같은 Rapfi라도 개발/최종 평가를 별도 조건/목록으로 관리한다. 결과를 보고 선택/수정했다면 그 자료는 소비된 개발 평가이며 독립 최종 평가로 재소개하지 않는다. 새 최종 주장에는 새 미사용 평가 또는 선택 편향의 명시가 필요하다.

## 실행 단위와 재현 기록

같은 시작 배치에서 후보와 상대의 흑백을 바꾼 두 대국을 한 **배치 쌍**으로 관리한다. 규칙/오프닝·시작 ID/전체 수순·색 소유·시드·모델/코드/데이터 계약 버전·상대 버전/해시/설정·시간/스레드/CPU·메모리·GPU/장치·추론 정밀도·MCTS 예산/캐시/트리 재사용·실제 자원 측정을 기록한다. 게임/배치 쌍 ID·예정/완료/재실행 ID를 보존한다.

평가 설정과 배치 목록을 실행 전에 고정한다. 한쪽 색에서 시작 실패/취소가 있으면 쌍 불완전을 표시하고 사전에 정한 재실행 정책을 따른다. 유리한 결과만 골라 쌍을 완성하지 않는다. 배치가 공유하는 출처/오프닝 계열이 있으면 그 그룹/상관도 기록한다.

| 예산/용도 | 해석 |
|---|---|
| 고정 탐색량 | 모델/탐색 비교 시 simulations/방문/추론 호출 등 단위를 명시. 논리 방문 수와 실제 신경망 호출/캐시 hit를 함께 기록. 같은 이름의 숫자가 다른 엔진에서 같은 계산량이라는 보장은 없음 |
| 고정 시간 | 같은 하드웨어/스레드/장치·한 수/전체 제한·초기화/로드 비용 계측으로 실제 성능 비교. 탐색량도 측정해 계산량 증가와 모델 개선을 구분 |
| 빠른 진단 | 줄인 배치/예산·모의/단순 상대·제한된 수순 등 목적을 명시. 외부 실행기의 중간 중단을 무승부로 세지 않으며 대회 프로필 평가와 합치지 않음 |
| 대회 프로필 평가 | 선정된 공식 대상·심판·오프닝/수순/시간/CPU/메모리/pondering·의존성으로 실행. 빠른 진단 통과로 대체하지 않음 |

외부 Rapfi가 동일한 탐색량 제한을 지원하는지 확인하지 않은 상태에서 고정 탐색량 대등 비교를 주장하지 않는다. 미지원이면 해당 비교는 자체 모델 간으로 제한하고 Rapfi에는 검증된 시간/자원 조건을 사용한다. GPU 사용은 기록하고 목표 리그 확인 전 대회에서 허용된다고 가정하지 않는다. 현재 기본 어댑터 제한을 문서만으로 변경하지 않는다.

## 대국 집계와 오류

후보 관점에서 W/D/L을 집계하며 상대·프로필·예산·개발/최종 평가별로 분리한다. 규칙상 승패/무승부와 운영상 판정 승패는 모두 사유를 보존한다.

| 사건 | 대회 결과/학습과 별개의 평가 집계 |
|---|---|
| 보드 승패·프로필 무승부·확인된 기권/금수패 | 해당 결과의 W/D/L과 종료 유형을 함께 기록 |
| 대국 중 시간패·불법 수·프로세스/응답 오류 | 적용된 대회 판정 승패와 오류 원인/귀책을 모두 기록. 검증된 판정이면 대회 결과 점수에는 포함하되 오류율 별도 보고 |
| 시작 실패·취소·판정 충돌·결과 미확정/무효 | 정상 패배/무승부가 아님. W/D/L 분모에서 제외하고 수/비율·불완전 쌍/재실행을 별도 공개 |
| 외부 길이 제한으로 중단 | 프로필의 정상 종료가 아니면 무승부로 계산하지 않음 |

예정 대국 수, 시작/완료/유효 판정/보드 결과 수, W/D/L, 각 오류/시작 실패/취소/무효, 완전한 배치 쌍 수를 함께 보고한다. 기본 대회 결과 점수는 `(W+0.5*D)/(W+D+L)`이며 분모0이면 산출 불가다. 정상 보드 결과만의 점수를 추가하면 별도 이름/분모와 제외 이유를 명시하고 기본 점수/오류율을 숨기지 않는다. 오류 대국의 학습 사용은 [데이터 계약](data-contract.md)이며 평가 점수와 자동 연결하지 않는다.

시작 실패율은 시작 시도 수, 대국 중 오류율은 실제 시작한 대국 수를 분모로 삼고 후보/상대 귀책과 유형별 건수를 함께 제시한다. 취소/무효는 시도 기준 건수/비율과 영향받은 배치 쌍을 공개한다. 분모0의 비율은 산출 불가이며 누락을0%로 표시하지 않는다.

불확실성은 독립 대국으로 가정한 이항 오차만으로 처리하지 않는다. 기본 보고 방식은 배치 쌍을 묶어 재표집하는 **95% paired cluster bootstrap 백분위 구간**과 점수/표본 수다. 같은 오프닝 계열이 여러 쌍이면 그 상위 그룹을 단위로 삼고 선언한다. 재표집 횟수/시드·그룹 목록·불완전 쌍 처리 규칙을 평가 전에 고정하고 기록한다. 재표집 횟수의 초기 권장안은10000회이며 실행기 구현 전 확정한다. 표본/그룹이 너무 적거나 한 그룹뿐이면 구간이 퇴화/불안정함을 표시하고 확정적 우열을 주장하지 않는다. Elo는 상대 풀/모형/오차를 정한 뒤 보조 지표로 도입하며 점수에서 임의 환산하지 않는다.

## 비결정성과 보고 축

시드만 같다고 정확한 수순/비트 재현을 약속하지 않는다. GPU 커널/축약·추론 backend/정밀도, 병렬 MCTS의 탐색/응답 순서, 스레드 수·OS 스케줄·시간 제한/부하, 엔진 버전/캐시/트리 재사용·프로세스 초기화, 데이터 순서와 도구 버전을 기록한다. 결정적 모드 지원 여부·허용 수치 차이·반복 실행 결과와 재현 불가 항목을 공개한다. 체크포인트 재개 성공과 완전히 동일한 자기 대국 재현은 별도다.

보고는 다음을 분리한다: 학습/검증 손실과 학습 재개 성공, 실제 대국 실력, 모델 단독 대비 MCTS 효과, 프로토콜 수신/응답, 최종 대회 조건 준수. 자체 모델의 합법 완결 대국은 기능 검증이고 강한 AI 완성 판정이 아니다. 수신 프로토콜 응답도 제출 적합성 완료가 아니다.

## 실력 목표의 결정 시점과 완료 기준

승률/Elo 숫자는 아직 확정하지 않는다. 먼저 이전 모델/단순 기준/Rapfi의 버전·보류 배치·색 교대·예산·오류 허용/표본 예산을 정한 **별도 예비 평가**로 측정 가능성과 비용을 확인한다. 그 뒤 본격적인 P7/모델 승격·최종 미사용 평가 전에 사용자와 실력 목표/개선 기준을 결정한다. 권장 기준은 같은 자원의 이전 체크포인트 대비 개선과 단순 기준/Rapfi 점수를 각각 표본/구간·오류율과 함께 보는 방식이다. 단일 상대 소수 승률로 목표를 정하거나 완료 선언하지 않는다.

실행기 완료 기준은 고정된 배치 쌍·세 상대 역할 분리·버전/자원·정상/오류 집계·점수/구간 재현·중단/재개와 중복 방지·개발/최종 목록 분리가 실제 기록으로 검증되는 것이다. 대회 적합성은 별도 P8에서 목표 공고/실제 심판·패키지·자원·정상 종료까지 확인한다. GUI/Swap2의 목표 리그와 무관한 미완료는 일반 렌주 학습/평가 전체의 자동 차단 조건이 아니다. 기존 별도 Swap2 호환성 요구 자체는 계속 추적한다.
