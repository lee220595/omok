# 외부 벤치마크·실력·제출 평가 계약

2026-10-28 설계. **범용 평가 실행기·아래 통계/프로필 전환 기능은 미구현**이다. 현재 고정 simulation의 [PUCT/정책 단독 소규모 개발 비교](puct-search.md)는 구현했다. 동일 시간/범용 외부 평가·아래 통계 프로필 전체는 미구현이며 기존 Rapfi probe/GUI 검증을 반복 평가 완료로 보지 않는다. [Rapfi 어댑터](rapfi-integration.md)의 실제 통신/자원/오류 정책과 [환경 사건 구분](headless-environment-contract.md)을 재사용한다.

## 평가 상대와 데이터의 역할

| 대상 | 역할 |
|---|---|
| 이전 자체 모델 | 회귀/승격·학습 전후 비교. 코드/체크포인트·추론/MCTS 조건 고정 |
| 단순 기준 플레이어 | 합법성/파이프라인·기본 성능 진단. 모의/단순 수 선택기를 강한 자체 AI로 소개하지 않음 |
| Rapfi | **중간·최종 평가용 고정 외부 벤치마크**. 현재 학습 상대·정답 생성 교사로 사용하지 않으며 결과/기보를 학습 경험/정답으로 전용하지 않음 |
| 이후 다른 엔진 | 상대 다양성/일반화 검증용 별도 벤치마크 후보. 선정/권리/규칙/프로필 검증 후 추가, Rapfi/이전 모델 결과와 임의 합산하지 않음 |

상대가 아직 없으면 부재/미검증을 기록한다. Rapfi의 실행 파일·모델/가중치 해시·config·버전·CPU용 빌드를 벤치마크 프로필에 고정한다. 바꾸면 새 프로필이며 기존과 조건이 같다고 가정하지 않는다. 기존 사람 대 Rapfi는 수동 관찰/디버깅용으로 유지한다.

학습·검증·평가 데이터/시작 배치·상대 계보를 구분한다. 개발 중 반복 확인하고 모델/하이퍼파라미터를 고르는 평가는 **개발 평가**다. 최종 미사용 배치/설정/상대 조건은 후보 모델/설정과 평가 절차를 고정한 뒤 사용한다. 같은 Rapfi라도 개발/최종 평가를 별도 조건/목록으로 관리한다. 결과를 보고 선택/수정했다면 그 자료는 소비된 개발 평가이며 독립 최종 평가로 재소개하지 않는다. 새 최종 주장에는 새 미사용 평가 또는 선택 편향의 명시가 필요하다.

## 실행 단위와 재현 기록

같은 시작 배치에서 후보와 상대의 흑백을 바꾼 두 대국을 한 **배치 쌍**으로 관리한다. 규칙/오프닝·시작 ID/전체 수순·색 소유·시드·모델/코드/데이터 계약 버전·상대 버전/해시/설정·시간/스레드/CPU·메모리·GPU/장치·추론 정밀도·MCTS 예산/캐시/트리 재사용·실제 자원 측정을 기록한다. 게임/배치 쌍 ID·예정/완료/재실행 ID를 보존한다.

평가 설정과 배치 목록을 실행 전에 고정한다. 한쪽 색에서 시작 실패/취소가 있으면 쌍 불완전을 표시하고 사전에 정한 재실행 정책을 따른다. 유리한 결과만 골라 쌍을 완성하지 않는다. 배치가 공유하는 출처/오프닝 계열이 있으면 그 그룹/상관도 기록한다.

| 예산/용도 | 해석 |
|---|---|
| 고정 탐색량 | 모델/탐색 비교 시 simulations/방문/추론 호출 등 단위를 명시. 논리 방문 수와 실제 신경망 호출/캐시 hit를 함께 기록. 같은 이름의 숫자가 다른 엔진에서 같은 계산량이라는 보장은 없음 |
| 고정 시간 | 같은 하드웨어/스레드/장치·한 수/전체 제한·초기화/로드 비용 계측으로 실제 성능 비교. 탐색량도 측정해 계산량 증가와 모델 개선을 구분 |
| 빠른 진단 | 줄인 배치/예산·모의/단순 상대·제한된 수순 등 목적을 명시. 외부 실행기의 중간 중단을 무승부로 세지 않으며 대회 프로필 평가와 합치지 않음 |
| 대회 프로필 평가 | 선정된 공식 대상·심판·오프닝/수순/시간/CPU/메모리/pondering·의존성으로 실행. 빠른 진단 통과로 대체하지 않음 |

외부 Rapfi가 동일한 탐색량 제한을 지원하는지 확인하지 않은 상태에서 고정 탐색량 대등 비교를 주장하지 않는다. 미지원이면 해당 비교는 자체 모델 간으로 제한하고 Rapfi에는 검증된 시간/자원 조건을 사용한다. GPU 사용은 기록하고 목표 리그 확인 전 대회에서 허용된다고 가정하지 않는다. 현재 기본 어댑터 제한을 문서만으로 변경하지 않는다.

## 대국 집계와 오류

후보 관점에서 W/D/L을 집계하며 상대·프로필·예산·개발/최종 평가별로 분리한다. 규칙상 승패/무승부와 운영상 판정 승패는 모두 사유를 보존한다.

| 사건 | 대회 결과/학습과 별개의 평가 집계 |
|---|---|
| 보드 승패·프로필 무승부·확인된 기권/금수패 | 해당 결과의 W/D/L과 종료 유형을 함께 기록 |
| 대국 중 시간패·불법 수·프로세스/응답 오류 | 적용된 대회 판정 승패와 오류 원인/귀책을 모두 기록. 검증된 판정이면 대회 결과 점수에는 포함하되 오류율 별도 보고 |
| 시작 실패·취소·판정 충돌·결과 미확정/무효 | 정상 패배/무승부가 아님. W/D/L 분모에서 제외하고 수/비율·불완전 쌍/재실행을 별도 공개 |
| 외부 길이 제한으로 중단 | 프로필의 정상 종료가 아니면 무승부로 계산하지 않음 |

예정 대국 수, 시작/완료/유효 판정/보드 결과 수, W/D/L, 각 오류/시작 실패/취소/무효, 완전한 배치 쌍 수를 함께 보고한다. 기본 대회 결과 점수는 `(W+0.5*D)/(W+D+L)`이며 분모0이면 산출 불가다. 정상 보드 결과만의 점수를 추가하면 별도 이름/분모와 제외 이유를 명시하고 기본 점수/오류율을 숨기지 않는다. 오류 대국의 학습 사용은 [데이터 계약](data-contract.md)이며 평가 점수와 자동 연결하지 않는다.

시작 실패율은 시작 시도 수, 대국 중 오류율은 실제 시작한 대국 수를 분모로 삼고 후보/상대 귀책과 유형별 건수를 함께 제시한다. 취소/무효는 시도 기준 건수/비율과 영향받은 배치 쌍을 공개한다. 분모0의 비율은 산출 불가이며 누락을0%로 표시하지 않는다.

불확실성은 독립 대국으로 가정한 이항 오차만으로 처리하지 않는다. 기본 보고 방식은 배치 쌍을 묶어 재표집하는 **95% paired cluster bootstrap 백분위 구간**과 점수/표본 수다. 같은 오프닝 계열이 여러 쌍이면 그 상위 그룹을 단위로 삼고 선언한다. 재표집 횟수/시드·그룹 목록·불완전 쌍 처리 규칙을 평가 전에 고정하고 기록한다. 재표집 횟수의 초기 권장안은10000회이며 실행기 구현 전 확정한다. 표본/그룹이 너무 적거나 한 그룹뿐이면 구간이 퇴화/불안정함을 표시하고 확정적 우열을 주장하지 않는다. Elo는 상대 풀/모형/오차를 정한 뒤 보조 지표로 도입하며 점수에서 임의 환산하지 않는다.

## 비결정성과 보고 축

시드만 같다고 정확한 수순/비트 재현을 약속하지 않는다. GPU 커널/축약·추론 backend/정밀도, 병렬 MCTS의 탐색/응답 순서, 스레드 수·OS 스케줄·시간 제한/부하, 엔진 버전/캐시/트리 재사용·프로세스 초기화, 데이터 순서와 도구 버전을 기록한다. 결정적 모드 지원 여부·허용 수치 차이·반복 실행 결과와 재현 불가 항목을 공개한다. 체크포인트 재개 성공과 완전히 동일한 자기 대국 재현은 별도다.

보고는 다음을 분리한다: 학습/검증 손실과 학습 재개 성공, 실제 대국 실력, 모델 단독 대비 MCTS 효과, 프로토콜 수신/응답, 최종 대회 조건 준수. 자체 모델의 합법 완결 대국은 기능 검증이고 강한 AI 완성 판정이 아니다. 수신 프로토콜 응답도 제출 적합성 완료가 아니다.

## 실력 목표의 결정 시점과 완료 기준

승률/Elo 숫자는 아직 확정하지 않는다. 먼저 이전 모델/단순 기준/Rapfi의 버전·보류 배치·색 교대·예산·오류 허용/표본 예산을 정한 **별도 예비 평가**로 측정 가능성과 비용을 확인한다. 그 뒤 본격적인 P7/모델 승격·최종 미사용 평가 전에 사용자와 실력 목표/개선 기준을 결정한다. 권장 기준은 같은 자원의 이전 체크포인트 대비 개선과 단순 기준/Rapfi 점수를 각각 표본/구간·오류율과 함께 보는 방식이다. 단일 상대 소수 승률로 목표를 정하거나 완료 선언하지 않는다.

실행기 완료 기준은 고정된 배치 쌍·세 상대 역할 분리·버전/자원·정상/오류 집계·점수/구간 재현·중단/재개와 중복 방지·개발/최종 목록 분리가 실제 기록으로 검증되는 것이다. 대회 적합성은 별도 P8에서 목표 공고/실제 심판·패키지·자원·정상 종료까지 확인한다. GUI/Swap2의 목표 리그와 무관한 미완료는 일반 렌주 학습/평가 전체의 자동 차단 조건이 아니다. 기존 별도 Swap2 호환성 요구 자체는 계속 추적한다.

| 고정 전술 | test_mcts의 통제 평가기 승리/방어/부호 회귀를 재사용, 실제 CNN용 검토 세트는 추가 필요 | 지정 모델/선택 방식/예산의 허용 정답 충족. 규칙 자체의 정답이나 모든 전술 보증과 다름 |

정책 단독과 PUCT는 **같은 checkpoint**를 고정해 탐색 효과를 비교한다. 향후 RL은 이전 모델과 새 모델의 정책 단독끼리, 동일 PUCT 설정끼리를 각각 비교해 모델 업데이트 효과와 탐색량 효과를 분리한다. 루트 예산/시간/seed·시작 배치별 흑백 쌍을 고정한다. 현재 compare_search는 고정 simulation 비교이며 하드 시간 예산·외부 엔진·CI·승격 판정은 미구현이다. Rapfi는 기존 평가 전용 역할을 유지한다.

### 전술 세트의 논리 형식 — 파일/실행기 미구현

| 필드 | 필수 의미 |
|---|---|
| 식별/버전/권리 | 세트/문제 ID·schema·내용 해시·출처/이용 조건·검토 상태/담당/근거 버전 |
| 규칙/시작/재현 | 지원 프로필/버전·원본 시작 방식/ID·순서 있는 재현 수순/색·준비 돌/실제 actor·현재 배정/차례/수순. 불법/종료 상태는 일반 선택 문제로 쓰지 않음 |
| 허용 정답 | row-major225의 비어 있지 않은 허용 action 집합. 각 답은 해당 snapshot의 C++ 마스크에서 합법이어야 하며 선택 action이 집합에 속하면 통과 |
| 정답 근거 | 직접 검토한 승리/필수 방어/수읽기 설명과 대응 fixture/공식 규칙 근거. 현재 모델/PUCT가 고른 수를 그대로 정답으로 승격하지 않음 |
| 필수 여부/대상 | 필수/진단용·문제 범주·적용 대상(policy/PUCT/RL 모델)·고정 simulation 또는 별도 검증한 시간 예산·tie/seed·채점 규칙 |
| 결과/증거 | checkpoint/코드/DLL/설정·선택/분포·판정/지연·통과/실패/보류와 이유·감시 이벤트 ID |

예시 **검토 후보**는 test_mcts의 즉시 승리 배치 `a8a1b8c1c8e1d8g1`다. 현재 테스트는 흑 차례에 action109(row7,column4)의 정확한5목을 통제 평가기로 확인한다. 이 사실을 실제 CNN의 필수 전술 세트 통과로 바꾸지 않는다. 세트 버전/정답 근거 검토·적용 모드/예산·필수 여부를 고정하기 전 승격 관문은 판단 보류다. 필수 문제 한 건 실패는 **그 선언된 전술 관문** 실패이며 실력 전체/규칙 엔진 실패와 구분한다. 진단 문제 실패는 주의로 집계하고 필수/진단 분모를 따로 보고한다. 검사 후 필수 여부/허용 답을 유리하게 바꾸지 않는다.

### PUCT 통계와 검증 수준

실제 `mcts.search`의 정의와 동률/관점은 [PUCT 안내](puct-search.md)를 단일 기준으로 사용한다. **성공한 현재 순차 검색**의 불변조건은 다음과 같다.

- 루트 expansion은 simulation에서 제외한다. 설정 S는 완료된 root→leaf→backup 순회 수다. root 방문225개 합과 search.simulations는 S, visit_distribution[a]는 root_visits[a]/S다.
- network_evaluations는 성공한 모델 평가 횟수이며 초기 루트 평가1회를 포함한다. terminal_hits는 NN 대신 실제 결과를 쓴 leaf 도달 횟수(서로 다른 종료 국면 수가 아님)다. 따라서 `network_evaluations + terminal_hits = S+1`이다. `clones = S+1`은 base clone1회+simulation별 clone이며 깊이/전이 수와 다르다.
- transitions는 clone에서 성공한 경로 착수 수의 합이다. root/각 edge의 N/W/Q는 부모 actor 관점, 반환 value는 루트 확장의 NN 값이고 root_q는 선택 edge의 Q다. 이 값들을 최종 승패 라벨로 혼용하지 않는다. 실패 중 partial 통계에는 성공 등식을 무조건 요구하지 않는다.
- 향후 메타데이터 검사는 형상/유한성·정수 비음수 방문·S/NN/terminal/clone 정합·분포 정규화/불법 질량0·선택 action/Token·모델/설정 해시를 확인한다. 기존 compare_search는 root 방문 합/완료 simulation의 일부만 검사하므로 전체 검사를 이미 수행한다고 쓰지 않는다.

검증 수준은 따로 표시한다: **(1) 보드/기보 재생**은 기존 records.replay로 실제 수순·중간/최종 상태를 확인, **(2) 탐색 메타데이터 검사**는 저장 필드의 계약/내적 정합을 확인, **(3) 탐색 재실행**은 고정 모델/코드/DLL/설정·같은 시작/seed에서 선택/방문/Q를 다시 대조한다. (1)의 성공은 (2)/(3)을 증명하지 않는다. (2)도 조작된 통계를 모두 잡거나 동일 탐색 실행을 증명하지 못한다. 시간/OS 스케줄·backend 차이의 재현 오차는 별도 기록한다.

### 고정 체크포인트·평가 식별과 완료 단위 재개

현재 checkpoint.atomic_save의 임시 파일→flush/fsync→replace·내용 무결성 검사와 ModelPlayer.prepare의 파일 SHA256 확인을 재사용한다. 이것은 **단일 파일의 저장**이며 latest.pt/best.pt/metrics 전체의 트랜잭션이나 불변 후보 등록 기능은 아니다. best.pt는 학습 중 교체될 수 있으므로 학습 중 경로를 그대로 따라가며 평가하지 않는다.

후속 평가 후보는 저장 완료/호환성을 확인한 파일을 고정 보관하고 내용/파일 해시·선정 epoch/step·부모/종류를 등록한 **고정본**만 사용한다. 평가 시작/종료 시 고정본과 manifest의 일치를 확인하며 파일이 바뀌면 섞지 않고 실패 격리한다. 새 완료 marker/복사 API는 아직 없다. .tmp·손상/미완성·선정 근거 없는 파일을 정상 checkpoint로 간주하지 않는다.

평가 ID는 후보/상대 모델 해시·코드 commit/소스/DLL 해시·모델/관측/규칙·보상/라벨 정책 버전·학습 데이터/분할·전술/배치 세트 해시·정책/PUCT·예산/자원·seed/재현 설정·감시 기준 버전으로 조건을 식별한다. 기존 아티팩트에 없는 보상 프로필은 해당 없음/기존 board-outcome-v1을 명시하고 최신 의미를 소급하지 않는다. 코드나 데이터가 다른 실험을 같은 결과로 합치지 않는다.

기존 runner manifest/code_version와 comparison-manifest, trace·독립 재생·완료 대국 건너뛰기를 재사용한다. 대국 키는 평가 ID+시작 ID+배치 쌍 ID+후보 색+seed+대국 index, attempt는 별도 보존한다. **완료 유효 대국 한 건은 한 번만 편입**하고 summary 파일을 이어 더하는 대신 완료 기록에서 재구성한다. 재시도/재수신/다른 경로 복사를 새 대국으로 세지 않는다. 현재 재개는 같은 조건의 완료 대국 단위이며 중간 검색/학습 batch/대국 RNG에서 이어두는 기능이 아니다. 미완료는 attempt 보존 후 기존 방식으로 다시 시작한다.

같은 output의 동시 작성/환경 동시 호출은 계속 미지원이다. 새 실행은 별도 output을 쓰되 조건이 같은 기록을 합칠 때에도 평가/대국 ID 중복을 검사해야 한다. 강제 종료/전원 손실로 현재 대국/미완료 epoch·진행 로그가 유실될 수 있으며 atomic replace로 전체 실행 내구성을 주장하지 않는다. 감시 중단 요청도 저장 확인 전에는 완료가 아니다.

### 표본·승격 판단

평가 전에 배치 목록/흑백 쌍·최대 대국/계산 예산·필수 문제·검사 일정·최소 판정 표본/그룹·CI 방법·허용 오류/최소 개선폭을 명시한다. 숫자 기준은 예비 측정 후 본 평가 전에 결정하며 현재는 미정이다. 현재 12판/예산별4판의 개발 비교를 새 기준의 통과로 소급하지 않는다. 위의 기존 점수/95% 그룹 bootstrap 설계를 유지하되 실제 CI 실행은 아직 없다.

손실 감소는 학습 수치의 진전이고 대국 성능 개선과 다르다. 부족한 표본/불완전 쌍·기준 없음은 판단 보류, 관찰된 하락/망각/과적합 징후는 주의, 미리 확정한 필수 관문의 근거 있는 실패는 승격 차단이다. 반복 확인으로 유리한 순간에만 평가를 끝내거나 대국을 계속 추가하지 않는다. 중간 확인/순차 중단이 필요하면 절차/통계 보정을 미리 정하고, 그렇지 않으면 사전 예산 종료 후 판정한다. 개발 반복 세트와 최종 미사용 세트는 계속 분리한다.
