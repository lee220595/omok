# 렌주 판정 계약

2026-10-23 사용자 승인으로 규칙 명세·판정 모듈·자동 테스트를 구현했다. 기본은 기존 잠정 Gomocup 렌주이며 Swap2 후 렌주 모드를 추가하지 않았다. [사례 명세](renju-cases.md), [실제 검증](verification-rules.md)을 함께 읽는다.

## 근거의 구분

| 구분 | 고정 근거 | 적용·제한 |
|---|---|---|
| 공식 렌주 | [RIF International Rules of Renju](https://www.renju.net/rifrules/), 1996-05-02 제정·1998-05-03 정정, 3·9.1~9.3·10.1 | 돌 배열·사/열린 사/삼·재귀 예외·승리/금수·만판 판정 근거. RIF의 승리 주장 절차와 오프닝 전체를 도입하지 않음 |
| 대회 추가 정책 | [Gomocup 일반 안내](https://gomocup.org/detail-information/), 2026-10-23 확인 | 전문가 준비 오프닝, 패스 없음, 200수 자동 무승부. 최종 참가 연도·리그 확정과 구분 |
| 비교 심판 | [GomocupJudge 고정 소스](https://github.com/Gomocup/GomocupJudge/tree/56cfd7dc1a0d1ec06d29f44a26931f375ad05991), 커밋 `56cfd7dc1a0d1ec06d29f44a26931f375ad05991` | 공식 조직의 기존 조사 기준 커밋을 재사용. `client/check_forbid.py`, `client/ai_match.py`의 실제 판정 함수·루프를 비교 대상으로 선정. 미래 대회 서버가 이 버전임을 뜻하지 않음 |

RIF 9.2의 정확한 5목 우선 조건과 심판 `foulr`의 A5 선행 처리가 일치한다. 심판 `play`는 `len(opening)`에서 수순을 시작해 인덱스 200 전에 멈추고, 각 착수의 `make_move` 결과를 먼저 처리한다. 따라서 준비 배치는 총 200수에 포함하고 **200번째 수의 승리·금수를 무승부보다 먼저** 처리한다. 준비 배치를 200수 제한과 별도로 더 허용하지 않는다.

## 공개 API와 책임

헤더: `src/rules/include/omok/rules/renju.hpp`. 구현: `src/rules/renju.cpp`. `omok_rules`는 `omok_state`에만 의존하는 C++20 정적 라이브러리다. GUI·Windows·프로토콜·참가자 입력 권한에 의존하지 않는다.

| API | 검사·판정 | 하지 않는 일 |
|---|---|---|
| `validate_board_candidate(board, candidate)` | 범위·색 enum·전체 Cell enum·빈칸 검사, Reason 반환 | 차례·종료·금수·수순 검사 |
| `analyze_board(board, candidate)` | 구조 검사 후 후보를 놓았다고 가정해 국소 렌주·만판 판정 | 상태의 차례·이력·200수·과거 수의 합법성 검사 |
| `evaluate(state, candidate)` | 종료 여부, 구조 검사, 예정 색, 이미 200수인지 검사한 후 보드 판정. 정상 200번째 착수는 무승부로 변환 | 참가자 권한, 오프닝 진행, 상태 쓰기, 반칙패 적용 |

입력 보드는 **착수 전**의 고정 225칸 읽기 전용 span이다. 좌표는 상태와 동일한 `{row, column}`, 0~14다. 색은 참가자 A/B 및 엔진 자신/상대와 독립적이다. 원본 상태와 보드는 가상 착수·재귀 탐색에서도 변경하지 않는다. 판 밖 좌표를 패스로 해석하지 않는다.

`Decision`의 `Verdict`는 Invalid(구조/호출 문맥 오류), Forbidden(흑 금수), Legal(계속), Win(후보 색 승리), Draw다. `Reason`은 근거 하나를 반환한다. 흑의 정확한 5목은 모든 금수보다 우선하며, 백은 5개 이상이면 승리한다. 5목이 없는 흑의 장목·사사·금지 삼삼은 Forbidden이다. 복수 금수가 겹친 경우 표시 사유는 장목→사사→삼삼 순서다. 이 사유 선택을 별도 승패 우선 규정으로 해석하지 않는다.

Invalid의 검사 순서도 복수 오류의 제품 우선순위를 정한 것은 아니다. Forbidden은 **금수가 발생한다는 분석**이며 상대의 승리를 상태에 기록하지 않는다. 잘못된 GUI 요청과 엔진 불법 수의 제재는 이후 대국 제어가 승인된 정책에 따라 처리한다.

보드 분석은 마지막 후보를 지나는 선만 판정한다. 임의 보드에 이미 존재하는 과거 승리·금수, 수량·교대 불일치까지 보증하는 기보 검증기가 아니다. 오프닝·기보 복원은 수순 순서대로 별도 검증해야 한다. 이력을 건너뛰거나 보드 점유 수만 세어 준비 배치 수를 유추하지 않는다.

## 금수 분석 방법

- 네 방향에서 후보를 포함하는 최대 연속 길이를 구한다. 흑은 정확히 5와 6 이상을 구분한다.
- 사는 정확한 5를 완성할 수 있는 길이 5 구간에서 찾고 **구성하는 네 돌의 좌표 집합**으로 식별한다. 열린 사의 양끝은 같은 사다. 같은 방향의 서로 다른 돌 집합은 별개의 사로 센다. 완성해도 장목만 되는 구간은 사가 아니다.
- 삼은 후보를 포함하는 세 돌이 한 돌 추가로 양끝에서 정확한 5를 만들 수 있는 열린 사가 되는지 확인한다. 두 확장점이 있어도 세 돌 집합이 같으면 하나다.
- 확장점에 흑을 가상 배치한 뒤 동시에 5목을 만드는지, 장목·사사·금지 삼삼인지 검사한다. 삼삼의 예외는 같은 절차로 재귀 검사한다. 확장이 금수인 가짜 삼은 세지 않는다. 깊이를 임의로 잘라 합법으로 처리하지 않는다. 각 재귀는 빈칸 하나를 줄이므로 유한하다.
- 읽기 전용 입력을 사본으로 만들고 사본에서만 가상 배치·복구한다. 전역 가변 변수나 GUI 상태를 사용하지 않는다. 재귀 최악 시간·금수 표시 전체 225점의 반응성은 아직 성능 보증하지 않는다.

자체 구현은 좌표 집합 열거에 기반한다. GPL 비교 소스의 패턴 테이블이나 코드를 제품에 복사·번역하지 않았다. 비교 도구와 제품 판정은 별도 구현이다.

## 향후 대국 제어의 적용 계약

1. 단일 작성자가 현재 세션·버전·입력 참가자·오프닝 단계를 확인한다. 일반 착수는 `evaluate`, 준비 배치 분석은 `analyze_board`를 사용한다. 후속 구현된 색 선택·준비 복원·단계 전환은 [오프닝 계약](opening-contract.md)을 따른다. Swap2는 규칙 바인딩 전 렌주 evaluate에 연결하지 않는다.
2. 판정과 적용 사이에 상태가 달라지면 재판정한다. 이전 세션의 늦은 AI 응답은 폐기한다.
3. Invalid/Forbidden 요청을 `commit_placement`에 바로 전달하지 않는다. 로그와 제재·반칙패 기록은 대국 제어의 별도 정책이다. 비교 심판과 불일치하면 기존 승인대로 중단·로그·승패 미확정으로 둔다.
4. Legal/Win/Draw 배치는 상태 **사본**에 `commit_placement(실제 배치 참가자, 명시적 다음 색)`를 수행한다. 일반 대국의 다음 색은 제어 계층에서 교대시킨다. Win은 후보 색의 소유자를 찾아 `finish(Won{소유자})`, Draw는 `finish(Draw{})`를 사본에 기록한다. 모든 호출 성공 후 사본 전체를 공개 상태에 반영해 중간 상태가 노출되지 않게 한다. 이 조립 책임은 match 단계에서 구현한다.
5. 승자 색이 미배정이면 A/B를 추측하지 않는다. 색 확정 전 오프닝의 분석 결과를 일반 대국 승패로 자동 적용하지 않는다. 상태 `finish(Won{A/B})` 자체는 미배정 상태에서도 외부 결과를 기록할 수 있으므로 이 저장 계약과 제어 권한을 구분한다.

## 미해결·미검증 경계

현재 명세 사례에 구현을 막는 근거 충돌은 없다. 임의의 모든 합법 렌주 배치와 모든 재귀 깊이의 심판 일치를 증명한 것은 아니다. 불일치가 새로 발견되면 해당 배치·수순을 독립 사례로 남기고 공식 근거와 대조하며 기대값을 추측해 고정하지 않는다.

참가 연도·리그 및 그 운영 심판 버전, 공식 준비 오프닝 데이터의 출처·사용 조건, 전체 매니저/엔진 실행과 시간·자원·오류 처리는 후속 과제다. 준비 데이터 로더·순차 복원은 이후 오프닝 단계에서 구현했다. 이번 비교 버전 선정을 최종 대회 선정이나 매니저 연동 완료로 보고하지 않는다.
