# GUI 없는 대국 환경·기록/재생 계약

2026-10-28 설계. **DirectRenju/PreparedRenju의 Python 환경·순차 CLI·JSON trace 저장/재생을 구현했다**([실제 API와 검증](python-headless.md)). 아래는 논리 요청/반환 의미이며 실행 가능한 새 API/명령이 아니다. 실제 상태/판정/권한은 [state](state-model.md)·[rules](rules-spec.md)·[opening](opening-contract.md)·[match](match-contract.md)를 재사용한다.

## 경계와 공통 응답

환경은 단일 작성자의 Controller를 소유한다. 호출자는 보드/결과에 직접 쓰지 않는다. 요청에는 인터페이스 버전·요청 ID·대국 ID와 변경 요청의 예상 Token/actor를 포함한다. 응답은 요청 처리 상태, 현재 대국 ID/Token, 스냅샷/단계, 판정/이유, 대국 결과/종료 사유, 실행 중단 사유를 구분한다. 지원하지 않는 버전/프로필은 명시적 오류다.

현재 v1 지원 대상으로 DirectRenju와 복원 완료 PreparedRenju의15×15/200수 프로필을 계획한다. 현재 evaluate/로더의 고정 정책과 다른 프로필을 선언만 바꿔 실행하지 않는다. 프로필은 규칙/종료·시작 방식·시간/자원 ID/버전과 실제 지원 범위를 보존한다. 실행기의 작업 길이/중단 제한은 규칙 종료 프로필과 별개다.

| 논리 작업 | 입력 | 반환/효과 |
|---|---|---|
| 초기화 | 지원 프로필, DirectRenju, 흑 소유자A/B | 빈 보드/이력0·흑 차례·색 배정·새 대국 ID/Token. 이전 비동기 결과 격리 |
| 시작 배치 복원 | 프로필, 원본 Session 또는 ID/순서 있는 준비 데이터, 흑 소유자 | 기존 opening 검증 후 보드·이력/주체·배정·차례·오프닝 이벤트/ID·결과를 함께 공개. 실패 시 기존 환경 전체 보존 |
| 스냅샷/관측 | 대국 ID, 필요 시 예상 Token | 읽기 전용 보드·현재 참가자/색·배정·전체 수순/준비 수·단계·결과/사유·프로필/버전. 모델 ready일 때만 [관측 계약](model-contract.md)의 텐서 제공 |
| 합법 수 조회 | 같은 ID/Token의 일반 대국 | 현재 색으로 rules::evaluate를 사용한 bool225개와 처리 상태. 원본/이벤트/버전 불변. 종료는0마스크, 미지원 단계/blocked는 별도 이유 |
| 착수 | ID/Token, actor, 좌표 또는 명시적으로 변환한0..224행동 | 구조/권한 검사 뒤 기존 match::place 판정을 적용. 아래 Rejected/Applied/Adjudicated를 구분하고 최신 스냅샷 반환 |
| 결과 조회 | ID/Token | 진행/종료, winner A/B 또는 draw/aborted, 판정 근거, 정상 종료/실행 중단 구분. 보드에5목이 있는지만 검사해 결과를 재생성하지 않음 |
| 실행 중단/닫기 | ID/Token, 취소/외부 길이 제한 등 이유 | 실행 기록을 중단으로 보존. 기존 close/이미 종료된 결과 보존 계약을 따르고 정상 승무패 라벨을 만들지 않음 |
| 기록/재생 | 원본 시작Session과 순서 있는 승인 행동/종료 이벤트·프로필 | [정규화 기록](data-contract.md)의 최소 trace를 읽고 별도 사본에서 재실행. 매 단계 보드/이력/결과/이유 비교 후 공개, 불일치 시 원본 유지 |

재생은 무르기가 아니다. 임의 보드 주입 대신 원본 시작 배치와 실제 행동 순서를 검증한다. 준비 돌은 placed_by 없음, 일반 착수는 실제 actor, 색 선택은 별도 오프닝 이벤트다. 성공한 배치 수·색 소유·다음 참가자는 한 상태로 복원한다. Terminal 배치에는 다음 수를 요청하지 않는다. NotStarted/OpeningInput/RuleContractRequired에는 일반 대국/모델 요청을 보내지 않는다. 재개는 새 실행 ID/Token을 발급해 옛 결과를 차단하며 옛 ID는 계보로만 보존한다.

기권/금수 시도/실행 중단/명시적 엔진 오류도 배치 이력과 별도 사건으로 재생한다. 종료 이벤트만 보고 마지막 성공 돌을 금수 시도 돌로 추정하지 않는다. 재생 비교는 새 세션 ID/Token과 원본 ID의 대응을 기록하고 논리 상태/이벤트 순서를 비교한다. 옛 Token을 새 Controller에 그대로 제출하거나 새 ID 때문에 정상 재생을 불일치로 판정하지 않는다.

## 합법 마스크와 원자적 판정

합법 마스크는 **현재 일반 대국의 evaluate와 같은 우선순위**로 계산한다. Legal/Win/Draw 후보만 참, Invalid/Forbidden은 거짓이다. 정확한 흑5목이 동시 금수 조건보다 우선하는 기존 판정을 보존한다. 200번째 승리/금수는 무승부로 덮지 않는다. analyze_board만으로 차례/종료/수순 검사를 우회하지 않는다. 마스크가 참이어도 착수 시 최신 ID/Token/권한/규칙을 다시 확인한다.

| 요청/판정 | 환경 처리 | 보존/변경 |
|---|---|---|
| 형식/버전/ID·오래된 Token·actor/차례 오류, 판 밖/중복 | Rejected | 보드·이력·배정·차례·결과·이벤트·Token·프로필/실행 상태 전부 불변. 정상 보상/착수 이력 없음 |
| 일반 Legal | Applied | 돌/actor/이력·다음 차례·이벤트·revision을 일관되게 갱신 |
| Win/Draw | Applied + 정상 종료 | 최종 돌 기록 후 결과/사유 적용. 다음 차례 없음 |
| rules::Forbidden 금수 시도 | Adjudicated + 금수패 | **전체 상태 보존이 아님**. 시도 돌/성공 이력은 추가하지 않지만 백 승리·종료 이벤트/이유·revision을 갱신. 기존 Response.ok()가 참인 판정 적용 경로 |
| 준비 데이터 속 금수/잘못된 순서 | 복원 거부 | 참가자 반칙패가 아닌 입력 데이터 오류. 복원 전 환경 전체 보존 |

학습 행동 선택은 금수를 마스크로 막는다. 마스크를 무시해 실제 금수를 요청했으면 기존 반칙패를 적용하며 재입력으로 바꾸지 않는다. 해당 시도는225개 정책의 합법 정답이 아니다. 구조 오류 거부와 이 반칙 판정을 하나의 failure로 묶지 않는다.

[규칙 심판 감시](monitoring-contract.md)는 기존 snapshot/mask/step의 동일 환경/Token과 코어 판정을 연결한다. 마스킹 전 불법 확률 경향과 마스킹 후 실제 불법 선택을 별도로 보고하고, 후자는 변환/마스크/상태 불일치를 조사한다. 기존 mask/적용 일치 검증을 독립 규칙 정답의 증명으로 오해하지 않는다. 새 판정기를 Python에 만들지 않는다.

외부 엔진의 잘못된 형식/불법 좌표는 어댑터가 기존 engine_failure 정책으로 반칙패/중단을 적용할 수 있다. 이는 일반 환경 요청의 단순 Rejected와 다른 **명시적인 엔진 오류 처리 경로**이며 종료 이벤트를 기록한다. 어떤 오류를 학습으로 사용할지는 아래/데이터 계약을 따른다.

## 정상 종료와 실행 중단의 두 축

논리 응답은 대국 결과와 학습 episode 상태를 분리한다. `terminated`는 지원 규칙/확인된 정상 종료, `truncated`는 실행 사정으로 경험을 완결하지 못한 경우이며 결과 라벨 자격과 혼동하지 않는다. 실제 C++에 이 필드가 이미 있다는 뜻은 아니다.

| 사건 | 대국/실행 기록 | 학습 처리 |
|---|---|---|
| 정확한5목·백5목 이상·프로필의200수/만판 | 정상 종료, terminated=true | 확인된 결과와 라벨 정책에 따라 최종 보상/가치 목표 생성 |
| 기권·금수패 | 확인된 참가자 승패와 별도 종료 사유 | terminated=true이나 정책/가치 샘플 자격은 별도. 시도/기권을 일반 착수 정답으로 쓰지 않음 |
| 학습 실행기의 임의 길이/작업 시간 제한·취소 | truncated=true, 종료 이유 보존. 필요 시 기존 게임 Aborted/Closed | 패배나 draw0을 자동 부여하지 않음. 가치 목표 없음 |
| 엔진 시간 초과·비정상 종료·응답/좌표 오류 | 대회 정책상 승패가 있을 수 있으며 그대로 보존. 학습 실행은 오류/truncated로 표시 | 현재 기본 학습 경로는 격리, 정상 승패 보상에 자동 혼합하지 않음 |
| 시작 실패·판정 충돌·결과 미확정 | 시작 실패/중단·무효와 알려진 사실만 보존 | 정상 패배/무승부/성공 episode로 계산하지 않음 |
| 진행 중 합법 수0 | blocked 이유와0마스크, 규칙 판정은 미확정 | 모델/MCTS/착수 요청 중지, 필요 시 실행 보류/truncated. draw/패배/패스 생성 금지 |

200수는 선택 프로필의 정상 종료다. 실행기 길이 제한이 우연히200과 같더라도 동일한 사건이 아니다. 정상 종료 수와 실행 제한이 함께 도달하면 이미 적용된 규칙 결과를 먼저 보존하고 나중에 중단으로 덮지 않는다. 이미 끝난 게임을 닫아도 기존 결과는 유지한다.

## 보상·관점·최종 결과 전달

적격한 최종 결과에 대해 승자+1/패자-1/무승부0, 성공한 비종료 전이의 즉시 보상0을 기본 결과 의미로 정의한다. 거부/중단/오류에는 수치0을 정상 보상인 것처럼 반환하지 않고 보상 없음/미확정을 표시한다. shaping·비정상 결과의 학습 사용·조기 기권 생성 정책은 별도 결정이다.

각 국면에 착수 전 현재 참가자/색 배정을 보존한다. 적격한 episode가 끝나면 그 국면의 참가자가 최종 승자이면 z=+1, 패자이면-1, 정상 draw이면0을 전달한다. 준비 돌 개수나 저장 샘플 번호의 홀짝으로 부호를 추정하지 않는다. 종료 때 next_participant가 지워져도 저장된 국면 관점으로 계산한다. WDL 목표는 할인/형태 보상 없이 최종 결과를 전파하며, 다른 보상 정의는 새 목표 버전/명시적 정책이 필요하다. MCTS 부호 규칙은 [모델 계약](model-contract.md)에 단일 정의한다.

기권/금수/시간패 등 세부 학습 포함 여부와 손실별 자격은 [데이터 계약](data-contract.md)을 따른다. 대국 결과가 존재한다는 이유만으로 중단 trajectory에 가치 정답을 채우지 않는다. nonterminal bootstrap을 도입하려면 별도 알고리즘/목표 정책으로 명시하며 현재 기본값으로 추정하지 않는다.

결과의 의미를 학습 목표로 바꾸는 책임과 후속 RL 연결 조건은 [보상 계약](reward-contract.md)에 둔다. 심판은 결과를 판정하고 감시자는 이상/증거/대응을 기록할 뿐 보상이나 학습률을 실시간 조정하지 않는다. 금수패-1 결과 매핑 권장과 현재 board-outcome-v1의 가치 보류를 구분한다.

## 완료 기준과 남은 규칙 결정

창 없이 초기화/복원→관측/마스크→착수/교대→결과/재초기화와 최소 trace 재생이 가능해야 한다. 같은 Token 스냅샷의 마스크/실제 판정, 정확한5목/금수 우선, 준비 포함200수, 정상 종료/중단 구분, 거부 시 전체 보존과 금수 시 결과 변경을 각각 시험한다. 재생의 metadata/색/차례/이력/이벤트 보존과 불일치 롤백, 오래된 응답 차단을 검증한다.

합법 수가 없는 진행 상태를 강제 패배/무승부로 확정하는 규칙은 아직 근거가 없다. 선택지는 규칙 근거를 확인해 별도 종료 규정을 추가하거나, 확인 전 blocked로 격리하는 방식이다. **현재 권장/적용 설계는 후자**이며 자동 draw 규칙을 추가하지 않는다. 이 쟁점은 해당 입력 경로만 보류하고 일반 합법 대국/학습 기반 전체를 막지 않는다.
