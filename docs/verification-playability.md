# 착수·차례 전환 GUI 재확인

2026-10-24, 기준 코드 `cdf72b6cf8896a9282777bf5badf3ac9c61b1747`, 작업 브랜치 `codex/rapfi-integration`. 정상 대국 여부 질문과 이전 작업 재개 지시에 따라 실제 창을 조작했다. fetch 후 HEAD/원격 작업 브랜치는 같았고 시작 시 추적 파일 변경은 없었다. main은 `a15a871`로 유지한다.

## 결과와 변경

착수와 자동 교대는 기존 match/GUI에 구현돼 있으며 실제 클릭으로 확인했다. 사용자에게 발생한 구체적인 현상은 재현하지 못해 원인을 확정하지 않는다. 실행 직후 빈 보드는 NotStarted이며 시작 버튼 전에는 착수할 수 없다. 기본 준비3수로 시작하면 백부터 두며, AI 차례에는 사람 클릭을 받지 않는다. 별도 다음 수 버튼은 없다.

혼동을 줄이도록 버튼을 **대국 시작**으로 바꾸고, 시작 대기·사람 클릭/자동 교대·Rapfi 응답 대기를 구분해 표시했다. 종료 뒤 금수 안내가 계속 “흑 차례에만…”으로 표시되던 문구는 “대국 종료 · 추가 착수 불가”로 고쳤다. 이미 종료된 준비 배치의 시작 안내도 분리했다. README와 배포 안내에 시작 절차를 보완했다. 규칙·match·오프닝·AI 동작과 빌드 스크립트는 변경하지 않았다.

## 실제 GUI 검증

Computer Use의 sky로 `dist/omok/omok.exe`를 실행하고 실제 버튼/교차점을 클릭했다. 아래 종료 배치들은 자체 작성 테스트 배치이며 공식 대회 데이터가 아니다.

| 항목 | 실제 관찰 |
|---|---|
| 기본 진행 | 준비 `h8i8g9` → 백 I9 → 흑 H7. 수순3→4→5, 차례 백B→흑A→백B, 마지막 돌/붉은 원 확인 |
| 승리 | `a8a1b8c1c8e1d8` → 백 G1 → 흑 E8. 9수 정확한5목·흑A 승리. 이후 F8 클릭에도9수/결과 유지 |
| 금수 | `g8a1h7c1i8e1h9g1` → H8의 X → 표시 끄기/켜기 → 흑 H8 클릭. 삼삼 반칙패·백B 승리, 이력8수/H8 빈칸 유지 |
| 200수 | GUI 목록의 `dev-draw-199-v1` 선택·시작 → 백 E14. 200수 자동 무승부/마지막 E14 확인 |
| 잘못된 가져오기 | 기본3수 대국 중 compact `h8h8`로 시작. 2수 중복 오류, 기존3수·차례·마지막 수 보존 |
| 기권/재시작 | 위 대국에서 백B 기권 → 흑A 승리 → 재시작. 편집 중인 `h8h8` 대신 원래3수/백B 복원 |
| 창 크기/최종 프로그램 | 안내 수정 후 재빌드 실행 → 최대화 → I9/H7 클릭. 바뀐 격자 좌표에 정확히 배치되고3→4→5/차례 전환 확인. 기권 후 새 종료 문구 확인 |
| Rapfi/최종 프로그램 | 사람A·흑 / RapfiB·백, 준비3수 → Rapfi I7(4수) → 사람 H7(5수) → Rapfi H6(6수). 이후 사람 흑 차례로 자동 교대 |
| 정상 닫기 | 두 번째 Rapfi 응답 후 Alt+F4. 창 소멸과 실제 호스트 omok/Rapfi 프로세스0개 확인 |

승리·금수·200수·가져오기/재시작은 문구 수정 전 기준 실행 파일로 확인했고, 최종 실행 파일에서는 기본 교대·최대화·기권·Rapfi 연결을 다시 확인했다. 문구만 바꾼 뒤 세 종료 경로를 모두 반복한 것으로 보고하지 않는다. 접근성 텍스트가 클릭 직후 이전 값을 반환한 경우 새 상태/화면을 읽어 전환 완료를 확인했다.

기본 금수 스캔은 GUI 출력0.13~0.23ms, 교차 위협8수는0.29~0.35ms였다. 이는 작은 배치의 관찰이며 최악 재귀 시간/장시간 반응성 보장이 아니다.

가장자리 G1 클릭에서 격자선 바로 바깥 입력 한 번은 거부됐고 안쪽으로 클릭하면 정상 착수됐다. hit는 기존 계약상 격자 바깥을 먼저 거부한다. 클릭 허용 범위를 변경하지 않았고 안내에 안쪽 클릭을 명시했다. 판정/차례 오류로 해석하지 않는다.

## 최종 빌드·자동 검증

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\build.ps1 -AliasParent "$env:TEMP\omok-rules-build"
ctest --test-dir .\build\native-release --output-on-failure --no-tests=error
Get-FileHash build/native-release/bin/omok.exe,dist/omok/omok.exe -Algorithm SHA256
& 'C:/Program Files/mingw64/bin/objdump.exe' -p .\dist\omok\omok.exe | Select-String 'DLL Name'
Get-Process -Name omok,'pbrain-rapfi*' -ErrorAction SilentlyContinue
```

- 기존 창을 Alt+F4로 닫은 뒤 configure·35개 컴파일/링크·install 성공(종료0), 경고 출력 없음. 기존 ASCII junction 유지.
- 최종 **CTest86/86 통과, 8.03초**. 상태14·규칙39·오프닝14·match14·AI5. 문구 변경만을 검사하는 테스트는 추가하지 않았다. AI5는 모의 엔진이며 실제 Rapfi 관찰과 구분한다.
- build/dist SHA256 일치: `472E232A14C82409669331C50D59382B6E5DDFFCC79FC84DD541B9649F45A838`.
- GUI DLL은 GDI32/KERNEL32/msvcrt/USER32. 추가 런타임 DLL 없음. 엔진/가중치를 변경·배포·커밋하지 않는다.
- 실제 Rapfi 첫 응답 로그 `engine-2-0-22532-1792829904446251100.log`: `8,6`→I7,11237.4ms, reaped1/forced0/exit0.
- 두 번째 `engine-2-2-34320-1792829939040853800.log`: `7,5`→H6,7269.09ms, reaped1/forced0/exit0. 원시 로그는 Git 제외인 실행 파일 옆 logs에 있다.
- 제한 실행의 프로세스 조회에서는 실제 GUI가 보이지 않아 호스트 조회 권한으로 재확인했다. 종료 판정은 후자의 프로세스0개 결과를 사용했다.
- 갱신한 지침/안내/인계/검증6문서의 로컬 링크77개 중 누락0, git diff --check 통과. external Rapfi·build/dist는 Git 제외를 재확인했다.

## 미검증과 다음 작업

이 기록은 기본 대국 진행의 실제 확인이다. 사용자가 관찰한 실패의 정확한 입력/실행 위치는 아직 알 수 없다. 준비 배치의 반대 A/B 배정·이미 종료된 배치의 새 안내는 이번 GUI에서 확인하지 않았으며 자동 회귀 근거와 구분한다. 모든 창 크기/모니터 DPI·병적 금수 재귀·장시간 자원 누수·긴 Rapfi 완결 대국·누적180초/자원 경계·개발 도구 없는 별도 Windows10/11은 미검증이다. 이전 [로컬 검증](verification-match.md), [Rapfi 검증](verification-rapfi.md)의 미검증을 전부 해소한 것으로 표시하지 않는다. 기본 준비 오프닝, Swap2 분리와 공식 데이터 미확보 상태도 유지한다.

다음은 남은 로컬 GUI 배정/종료 배치 확인과 긴 실제 엔진 대국·오류/자원 경계 검증이다. 전체 단계 완료/main 통합 여부는 그 결과와 기존 Git 정책에 따른다.
